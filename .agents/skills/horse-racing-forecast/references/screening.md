# Meeting screening workflow

原本0章、49章、標準予想フローを読み、対象日の各レースについて単一レースと同じCore/Finalを作る。情報量を減らすために確率整合や全馬評価を省略しない。

各Final後に、次を根拠付きで戦略へ保存する。

- `primary`: 的中確率と市場価格の両方に根拠があり、少数買い目で本線を表現できる。
- `high-payout`: 人気薄の台頭根拠と人気馬側の脆さがある。少額枠に分離する。
- `combined`: 信頼できる本線と過小評価馬が同居する。コアとオーバーレイを分ける。
- `skip`: 予想精度、価格、人気薄台頭根拠のいずれかが不足する。

分類完了後に次を実行する。

```text
node dist/cli.js screen report --date YYYY-MM-DD
```

比較表の未判定レースを残さず、見送りも正式記録にする。高配当を先に決めて評価を逆算しない。
