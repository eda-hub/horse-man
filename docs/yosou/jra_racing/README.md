# JRA重賞 予想記録運用

このディレクトリは、JRA重賞で実際に行った予想・買い目・結果・回顧・継続傾向を保存するための**長期記録の正本**である。予想方法そのものの正本は `docs/manual/` とし、ここでは各重賞への適用結果だけを管理する。

## 1. 基本原則

1. チャットは長期保存の正本ではないが、**結果確定前は発走前snapshotの一次参照元**として扱う。長期保存の正本は回顧完了後のGitとする。
2. **チャット単位と保存単位を分離する。** 1つのチャットで複数競馬場・複数レース・複数重賞を扱ってよいが、重賞記録は必ず1重賞1ファイルに分ける。
3. 各重賞は `docs/yosou/jra_racing/<race>.md` の固定パスを使い、本文には最新年度の実用状態を残す。過年度状態はGit履歴で参照する。
4. 翌年は前年チャットの継続を前提とせず、Git上の最新ルールと当該重賞ファイルから開始する。
5. 共通の保存・年度切替・チャット運用は本READMEを正本とする。個別レースファイルに旧来の共通運用文が残る場合は本READMEを優先し、レース固有の条件・傾向・注意事項だけを個別情報として扱う。
6. レースファイル内の過去傾向・回顧は共通Productionルールを上書きしない。共通ルールへの反映は `docs/manual/50_review.md` の検証・昇格手順を経る。
7. 事前予想・最終予想・買い目確定の段階では、記録だけを目的としたGit書き込みを行わない。Gitへの当年記録反映は回顧時に一括する。

## 2. 正本の役割分担

| 対象 | 正本 | 役割 |
|---|---|---|
| 予想ロジック・判断基準 | `docs/manual/` | 全レース共通のProduction / Shadow / 購入 / 回顧ルール |
| JRA重賞の最新年度記録 | `docs/yosou/jra_racing/<race>.md` | 予想、買い目、結果、回顧、当該重賞の継続傾向 |
| 過年度状態 | Git commit / pull request / tag | 過去のファイル状態のアーカイブ |
| チャット | 回顧前の事前snapshot一次参照元 | 発走前の予想・更新・買い目を時刻付きで固定し、回顧時にGitへ転記する |
| 進行中Shadow検証 | `docs/validation/` | 現行検証サイクルの一時データ |

優先順位は時点で分ける。**結果確定前の当年未回顧レースは、発走前時刻のチャットsnapshot > 過年度・既回顧のGit記録**とする。**回顧完了後はGitHub上の正本 > チャット内の古い文脈**とする。

## 3. ファイル単位とチャット単位

- 1重賞につき1ファイルを固定パスで使用する。
- ファイル名はレース名が判別できる英字名とする。
- 年度ごとの別ファイルや `old/` は作らない。
- 同じ重賞名が継続する限り、翌年も同じファイルを更新する。
- レース名変更・統合等で同一性が失われる場合だけ、別ファイル化を検討する。
- 通常レースの内容を重賞ファイルへ混在させない。
- 同じチャットに複数重賞がある場合も、それぞれ別の `<race>.md` に保存する。
- 同じチャットで扱った複数重賞は、同一ブランチ・同一PRでまとめて更新してよい。重賞ごとにコミットやPRを分ける必要はない。
- ユーザーから別途「このチャットをまとめて」と指示されなくても、JRA重賞は本規約の保存対象とする。
- GitHubへ書き込めない環境では保存済みと扱わず、その旨を明示する。

例：

```text
開催日単位のチャット
├── 通常レース
├── 重賞A → docs/yosou/jra_racing/<raceA>.md
└── 重賞B → docs/yosou/jra_racing/<raceB>.md
```

## 4. 予想開始時と年度切替

JRA重賞を扱うときは、次をGitHubから読む。

1. `docs/manual/README.md`
2. 依頼に必要な `docs/manual/` モジュール
3. 本 `docs/yosou/jra_racing/README.md`
4. 当該重賞の `<race>.md`（存在する場合）

### 同一年・同一レース

`docs/manual/00_core.md` の基準予想一意性と `baseline_forecast_id` 契約を適用する。

- チャットが変わっただけではProduction基準予想を作り直さない。
- 既存のProductionがあれば同じ `baseline_forecast_id` を引き継ぐ。
- 強い非価格情報による正式更新条件を満たした場合だけ新しい連番を発行する。
- オッズ更新だけではProduction基準予想IDを更新しない。
- 同じレースの `static_evidence_snapshot` が有効なら再利用し、最終予想では `dynamic_evidence_snapshot` と影響箇所だけを更新する。

### 年度が変わった場合

- 当年のProduction基準予想を新規作成し、新しい `baseline_forecast_id` を発行する。
- 前年の予想・買い目を当年のProductionへ直接コピーしない。
- 前年までに更新した構造的注意点、過去傾向、回顧上の検証候補は参照してよい。

## 5. レースファイルの更新方法

### 継続して残すもの

- 開催条件変更などの構造的注意点
- 過去実績を使った傾向分析・ローリング集計
- 継続傾向 / 弱まった傾向 / 新規傾向 / 例外
- 翌年に再検証するレース固有仮説

### 最新年度へ置き換えるもの

- レース基本情報・当年の出走情報
- Production基準予想 / Shadow比較
- 使用オッズ・市場評価
- 推奨買い目・実購入
- 結果・払戻・収支
- 当年固有の回顧

過年度の予想・買い目・収支を本文へ年表形式で蓄積しない。必要な場合はGit履歴から取得する。

## 6. 発走前固定と回顧時の一括保存

### 発走前

事前予想、Production基準予想、Shadow比較、最終予想、推奨買い目・実購入の確定または変更は、**Gitへ逐次保存せずチャット内で固定する**。

発走前snapshotは予想本文そのものが追跡できればよく、保存専用の長文を重複生成しない。最低限、対象レース、使用ルール版、`baseline_forecast_id`、情報基準時刻、Production基準予想、主要確率・予想確信度、必要なShadow差分、確定済みの市場評価・買い目を追跡可能にする。

同一レースで事前予想から最終予想へ進む場合は、`static_evidence_snapshot` を再利用し、取消・騎手変更・馬場・天候・当日馬体重・オッズ等の `dynamic_evidence_snapshot` だけを更新する。Production / Shadowは同じ `race_evidence_bundle` を参照する。

### 結果確定後 / 回顧

Gitへの保存は原則として回顧時に1回へまとめる。

1. 対象レースの発走時刻より前のチャット履歴から、Production / Shadow / 市場 / 買い目 / ユーザー提供情報のsnapshotを先に抽出する。
2. 事前snapshotを固定した後で、確定結果・払戻・収支・レース内容を確認する。
3. `docs/manual/50_review.md` に従って回顧し、結果から事前判断を書き換えない。
4. `docs/yosou/jra_racing/<race>.md` へ、当年の事前snapshot、最終状態、結果、回顧、翌年へ残す事項をまとめて反映する。
5. 必要な検証サイクル記録も同じ回顧作業内で更新する。

発走前チャット履歴を参照できない場合は、結果から事前予想を復元しない。`PRE_RACE_SNAPSHOT_UNAVAILABLE` として扱い、前向きKPIの正式サンプルへ算入しない。

## 7. 過去傾向と共通ルールの境界

レースファイル内の傾向は、その重賞を予想するときの**事前仮説・レース固有コンテキスト**として扱う。

- 単年結果だけを理由に共通Productionルールへ即昇格しない。
- 過去傾向を能力評価より優先した機械的な加点・消しにしない。
- レースファイルから `docs/manual/` の決定権を上書きしない。

共通ルールへ反映したい知見は `docs/manual/50_review.md` で検証し、必要なら別PRでOwnerモジュールへ反映する。

## 8. Git運用

- 現行ツリーのレースファイルは最新年度の実用状態を保つ。
- 過年度コピー用の年度別ファイル、`archive/`、`old/` は原則作らない。
- 過去状態はGit commit / pull request / tagから取得する。
- 更新は原則として作業ブランチ + pull requestで行う。ただし、予想中の記録目的更新は行わず、結果確定後の回顧時にまとめて実施する。
- 同じチャットの複数重賞は同じブランチ・PRで扱ってよいが、内容は各重賞ファイルへ分離する。
- 同じ情報を別の保存ファイルへ重複させない。

標準フローは、**「Gitから過去の正本を読む → チャットで予想・発走前snapshotを固定 → 予想中はGitへ書かない → 結果後の回顧でチャット履歴を参照 → JRA重賞だけ各固定ファイルへ一括保存 → 翌年はGitから再開」**とする。
