# JRA重賞 予想記録運用

このディレクトリは、JRA重賞について実際に行った予想・買い目・結果・回顧・継続傾向を保存するための**長期記録の正本**である。

予想方法そのものの正本は `docs/manual/` に置く。本ディレクトリはルール定義を複製せず、各重賞で最新ルールをどう適用したかを保存する。

## 1. 基本原則

1. **JRA重賞は原則として全レースを予想対象とする。**
2. 「見送り」は馬券購入の判断であり、重賞予想そのものを省略する意味ではない。
3. チャットは当該年度・当該レースを処理する一時的な実行環境とし、長期記録の正本にはしない。
4. 長期記録は `docs/yosou/jra_racing/<race>.md`、過年度状態はGit履歴を正本とする。
5. 翌年は前年チャットを継続することを前提とせず、GitHub上の最新ルールと当該レースファイルから新しい予想を開始する。
6. レースファイル内の過去傾向や回顧は、それ自体を共通Productionルールへ昇格させない。共通ルールへの反映は `docs/manual/50_review.md` の検証・昇格手順を経る。

## 2. 正本の役割分担

| 対象 | 正本 | 役割 |
|---|---|---|
| 予想ロジック・判断基準 | `docs/manual/` | 全レース共通のProduction / Shadow / 購入 / 回顧ルール |
| JRA重賞の最新年度記録 | `docs/yosou/jra_racing/<race>.md` | 予想、買い目、結果、回顧、当該重賞の継続傾向 |
| 過年度のファイル状態 | Git commit / pull request / tag | 過去の予想・買い目・結果・回顧のアーカイブ |
| チャット | 正本ではない | 当該年度・当該レースの一時的な作業環境 |
| 進行中Shadow検証 | `docs/validation/` | 現行検証サイクルの一時データ |

優先順位は、**GitHub上の正本 > チャット内の古い文脈**とする。

## 3. ファイル命名と単位

- 1重賞につき1ファイルを固定パスで使用する。
- ファイル名はレース名が判別できる英字名とする。
- 年度ごとに新規ファイルを増やさない。
- 同じ重賞名が継続する限り、翌年も同じファイルを更新する。
- レース名変更・統合・廃止などで同一性が失われる場合は、別ファイル化の要否を個別に判断する。

例：

```text
docs/yosou/jra_racing/centaurStakes.md
docs/yosou/jra_racing/challengeCup.md
```

## 4. 新年度の開始手順

同一重賞を翌年予想するときは、原則として**新しいチャットまたは新しい実行セッション**を開始する。

開始時に次をGitHubから読む。

1. `docs/manual/README.md`
2. 依頼に必要な `docs/manual/` モジュール
3. 本 `docs/yosou/jra_racing/README.md`
4. 当該重賞の `docs/yosou/jra_racing/<race>.md`（存在する場合）

前年チャットを読み直すことは必須ではない。必要な長期情報はレースファイルとGit履歴へ保存されていることを前提とする。

### 年度が変わった場合

- 当年のProduction基準予想は新規作成する。
- 新しい `baseline_forecast_id` を発行する。
- 前年の `baseline_forecast_id` を当年Productionへ流用しない。
- 前年の予想・買い目は当年の判断根拠として直接コピーしない。
- 前年までに更新された過去傾向・コース特性・条件変更履歴・回顧上の検証候補は参照してよい。

## 5. 同一年・同一レースを複数チャットで扱う場合

同一年・同一レースでは `docs/manual/00_core.md` の**同一レースの基準予想一意性**と `baseline_forecast_id` 契約を適用する。

- チャットが変わっただけではProduction基準予想を作り直さない。
- 既存のProductionがレースファイルまたは同レースの保存記録にある場合、その `baseline_forecast_id` を再利用する。
- 強い非価格情報による正式更新条件を満たした場合のみ、新しい連番の `baseline_forecast_id` を発行する。
- オッズ更新だけではProduction基準予想IDを更新しない。
- GitHub上に保存された同年記録とチャット内容が食い違う場合、保存時刻・情報時刻を確認したうえでGitHub上の正式保存記録を基準に復元する。

## 6. レースファイルに残すもの / 毎年置き換えるもの

### 継続して残すもの

- レース固有の開催条件変更履歴
- コース・時期・負担重量制度などの構造的注意点
- 過去実績を使った傾向分析
- 直近年のローリング集計
- 継続傾向 / 弱まった傾向 / 新規傾向 / 例外
- 翌年に再検証すべきレース固有の仮説

### 最新年度へ置き換えるもの

- レース基本情報
- 出走馬・枠順・馬体重・馬場等の当年情報
- Production基準予想
- Shadow比較予想
- 使用オッズ・市場評価
- 推奨買い目・実購入
- 結果・払戻・収支
- 当年固有の回顧

過年度の予想・買い目・収支を本文へ年表形式で蓄積しない。必要な場合はGit履歴から取得する。

## 7. 予想から保存までの標準フロー

```text
新年度・新しい実行環境
    ↓
docs/manual/README.md を読む
    ↓
必要な manual モジュールを読む
    ↓
本 README と当該重賞ファイルを読む
    ↓
当年Production基準予想を作成・固定
    ↓
必要に応じてShadow / 市場評価 / 買い目
    ↓
発走
    ↓
結果・払戻・実購入を確定
    ↓
回顧・傾向更新
    ↓
同じ <race>.md を最新年度内容へ更新
    ↓
Gitで保存
```

## 8. レースファイルの最低限の保存項目

各重賞ファイルは、当該年度について最低限次を含める。

- レース基本情報
  - 開催日
  - 競馬場
  - R
  - 距離
  - 馬場
  - 頭数
  - 発走時刻
  - 購入市場
  - 使用資金
- 使用した競馬予想ルール版
- `baseline_forecast_id`
- 事前メモ・当該重賞固有の傾向仮説
- Production基準予想
- 必要に応じたShadow比較
- 市場評価・買い目・実購入
- 確定結果・払戻・収支
- 回顧
- 過去傾向との一致 / 不一致
- 翌年へ残すレース固有の検証事項

## 9. 過去傾向と共通ルールの境界

レースファイル内の傾向は、当該重賞を予想するときの**事前仮説・レース固有コンテキスト**として扱う。

次を禁止する。

- 単年結果だけを理由に共通Productionルールへ即昇格すること
- 過去傾向の集計を能力評価より優先して機械的に加点・消しすること
- レースファイル側から `docs/manual/` の決定権を上書きすること

共通ルールへ反映したい知見は、結果後に `docs/manual/50_review.md` の手順で検証し、必要なら別PRでOwnerモジュールへ正式反映する。

## 10. Git運用

- 現在のレースファイルは常に最新年度の実用状態を保つ。
- 過年度ファイルのコピー用 `old/` や年度別アーカイブファイルは原則作成しない。
- 過去状態はGit commit / pull request / tagから取得する。
- 更新は原則として作業ブランチ + pull requestで行う。
- 同じ情報をチャット、レースファイル、別アーカイブへ重複保存しない。

この運用により、**「新しいチャット → Gitから最新ルールと当該重賞記録を取得 → 予想 → 結果・回顧を同じレースファイルへ保存」**を毎年の標準フローとする。
