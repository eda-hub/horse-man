# JRA重賞 年次予想ノート運用

このディレクトリは、JRA重賞ごとの**過去傾向、当年との照合、翌年予想課題**を保存する場所である。

共通境界は `docs/yosou/README.md` をOwnerとし、本ファイルはJRA重賞固有の運用だけを補足する。予想方法は `docs/manual/`、結果後の正式な回顧・検証は `docs/validation/` を正本とする。

## 1. 基本原則

1. 1重賞につき `docs/yosou/jra_racing/<race>.md` の固定パスを使用する。
2. 同じ重賞名が継続する限り翌年も同じファイルを更新し、過年度状態はGit履歴から参照する。
3. 重賞ファイルは翌年予想のための**レース固有知識**に限定する。
4. Production / Shadowの正式回顧、KPI、エラー分類、実購入収支、改善候補評価は `docs/validation/` に保存し、重賞ファイルへ重複保存しない。
5. 予想中は記録目的のGit書き込みを行わず、発走前のチャット回答をsnapshotとして扱う。
6. 結果確定後、validationの正式回顧を先に保存し、その後に重賞ファイルの傾向・翌年課題だけを更新する。
7. 個別ファイルに旧形式の「回顧」「収支」「KPI」等が残る場合、次回更新時に `docs/yosou/README.md` の境界を優先して整理する。

## 2. 予想開始時

JRA重賞を扱うときは次を読む。

1. `docs/manual/README.md`
2. 依頼に必要な `docs/manual/` モジュール
3. `docs/yosou/README.md`
4. 本 `docs/yosou/jra_racing/README.md`
5. 当該重賞の `<race>.md`（存在する場合）

同一年・同一レースでは `docs/manual/00_core.md` の `baseline_forecast_id` 契約を適用し、チャットが変わっただけではProductionを作り直さない。

## 3. 重賞ファイルへ残す内容

### 継続して残す

- 開催条件変更などの構造的注意点
- 過去実績を使ったローリング傾向
- 継続傾向 / 弱まった傾向 / 新規候補 / 例外
- レース固有の仮説
- 翌年に確認すべき課題・チェックリスト

### 当年終了後に更新する

- 当年のレース条件と最小限の結果
- 当年予想の簡潔な要約
- **過去傾向から見て当年予想がどうだったか**
- **当年結果で過去傾向がどう更新されたか**
- **翌年に向けた予想課題**

### 保存しない

- 詳細な発走前snapshot
- 詳細な買い目・実購入収支
- KPI・ROI
- A〜L等のエラー分類
- Shadow検証成績
- 反実仮想・非劣化判定
- 汎用ルールの改善候補判定

これらは `docs/validation/` の該当レコードへリンクする。

## 4. 回顧時の処理

JRA重賞の回顧では、

**チャットsnapshot復元 → validationへ正式回顧 → 重賞ファイルへ傾向照合・翌年課題を反映**

の順とする。

重賞ファイルでの「予想評価」は、汎用予想システムの採点ではなく、**その重賞の過去傾向・レース固有仮説が当年にどの程度有効だったか**を見るために行う。

共通ルールへ反映したい知見は、重賞ファイルから直接昇格させず、`docs/validation/` と `docs/manual/50_review.md` の手順を経る。

## 5. JRA固有の補足

- JRA重賞は原則として全レースを予想対象とし、「見送り」は購入判断として扱う。
- 当日馬体重等の取得は `docs/manual/README.md` のJRA当日馬体重取得契約に従う。
- 年度ごとの別ファイル、`archive/`、`old/` は原則作らない。
