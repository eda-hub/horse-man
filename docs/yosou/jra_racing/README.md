# JRA重賞 年次予想ノート運用

このディレクトリは、JRA重賞ごとの**通年のレース固有知識、当年結果との照合、翌年課題**を1重賞1固定ファイルで管理する。

共通境界は `docs/yosou/README.md` をOwnerとし、本ファイルはJRA固有の年次ノート構造をOwnerとする。予想・購入・snapshot・正式回顧の判断基準は `docs/manual/README.md` から参照し、ここで再定義しない。

## 1. 基本原則

1. 1重賞1固定パス。年度別ファイル、`archive/`、`old/` は作らない。
2. 過年度の照合文・正式回顧・買い目・収支・KPIは本文へ積み上げず、過去状態はGit履歴から参照する。
3. 通年の知識、比較に必要な過去事実、当年確定結果は有用な限り保持する。
4. レース固有傾向はProduction順位・確率・正式買い目へ自動反映しない。
5. 発走前snapshotの固定・永続化は `docs/manual/README.md` と `docs/manual/00_core.md` に従い、本READMEで再定義しない。
6. 正式回顧・KPI・エラー分類・実購入・Shadow評価は `docs/validation/` を正本とする。

## 2. 9章の固定構成

| 章 | 内容 |
|---|---|
| 1. 管理情報 | 対象年、結果年度、照合年度、次回利用年、状態、更新日 |
| 2. レース構造・適用条件 | コース、距離、時期、斤量条件、変更履歴、比較可能性 |
| 3. 通年の傾向・仮説 | 固定ID付きのユーザー蓄積傾向・データ由来仮説 |
| 4. 過去データ・集計条件 | 事実表、期間、母集団、分母・分子、欠測、出典 |
| 5. 当年の確定結果 | 開催条件、確定1～3着、照合に必要な事実、出典 |
| 6. 当年結果との照合 | 当年を除く比較根拠×当年事実×判定。単年度のみ |
| 7. 翌年へ向けた課題 | 問い、必要データ、実施時点、完了条件 |
| 8. 次回利用チェックリスト | レース固有の利用前確認 |
| 9. 出典・参照先 | 外部情報源、取得日、確定履歴・正式回顧参照 |

H2はこの9章に固定し、レース固有補足はH3以下に置く。未取得・対象外でも章を消さず理由を書く。

## 3. 管理情報と傾向台帳

状態は準備中／結果未確定／結果確認中／照合未完了／更新完了／開催中止を使う。暦が変わっただけで結果年度を進めない。

傾向・仮説には `T-001` 等の固定IDを付け、由来、適用条件、根拠、状態、注意点、最終確認日を記録する。ユーザー蓄積傾向は裏付け未取得でも保留・独立検証待ちとして保持できる。結果後に生まれた仮説を当年の事前仮説として扱わない。

## 4. 過去データ・集計条件

- 直近5開催を基本比較単位とするが、窓落ちだけで有用な事実データを削除しない。
- 開催場・距離・時期・斤量条件が異なる開催を単純合算しない。
- 集計には期間、対象、除外、母数、分子、定義、当年を含むか、取得日・出典を付ける。
- 欠測を0として扱わない。
- 上位3頭だけのデータから複勝率等を算出しない。

## 5. 当年結果と照合

結果確定済みなら、結果年度、開催日、競馬場、R、距離・コース、天候・馬場、出走頭数、確定1～3着、勝ち時計、結果出典・確認日を本文に残す。

第6章は単年度のみ保持し、2026年照合では原則2025年以前の根拠を使う。2026年込みの更新後集計を2026年の事前根拠へ逆用しない。傾向台帳の**全T-IDを第6章で1対1に対応**させ、根拠を項目ごとに確認する。照合できる項目は具体的に一致／一部一致／不一致を判定し、判定不能はその項目固有の不足理由または当年照合の対象外理由を書く。未確認のT-IDが残る場合は管理情報を `照合未完了` とする。結果後取得データは事後取得と明記する。

## 6. 翌年課題

`Q-001` 等の固定IDで、関連傾向ID、問い、必要データ・方法、実施時点、完了条件、状態を持つ。第3章の全T-IDについて、照合結果または対象外理由と翌年課題の対応関係を追跡できるようにする。**当年照合の再検証**では当年を除くデータだけを使い、**翌年向け傾向更新**では当年確定結果を含む最新データを使う。この2作業は期間・用途を分けて記録する。汎用的な購入監査・KPI改善はvalidationへ渡す。

## 7. 保持・削除基準

| 状況 | 扱い |
|---|---|
| 単年不一致・少数標本 | 弱化または保留。自動削除しない |
| 出典切れ | 確認済み範囲と欠測を記録し再確認課題にする |
| 開催条件変更 | 現行条件への適用を停止し、比較用途があれば保持 |
| 重複 | 根拠を統合 |
| 誤記・誤集計 | 訂正し旧状態はGit差分で追跡 |
| 比較・再検証にも用途なし | 理由をPRへ記載して削除可能 |

5開催窓からの退出、単年反例、出典切れだけを削除理由にしない。

## 8. 年次更新フロー

1. manualに従い正式回顧をvalidationへ保存する。事前記録がなければ後付けProductionを作らない。
2. 当年を含まない比較根拠を特定する。
3. 第5章を更新する。
4. 第6章を当年度分へ**置換**する。
5. 第3・4章へ継続利用する知識・根拠を反映する。
6. 第7・8章を整理する。
7. validation参照は存在を確認した確定commitの `blob/<commit>/<path>` を使う。

2027年結果確定後は2026年の照合文を2027年分へ置換する一方、比較・再集計に有用な2026年事実は第4章に残す。

## 9. 2026-09-22初回移行

旧ノートに混在していた買い目・収支・KPI・正式回顧を本文から除外した。現行validationに正式回顧がある開催は確定commitを参照し、存在しない旧記録は新規KPIへ後付け算入せず移行前ノートの確定commitを参照する。発走前snapshotの欠落・不適格性を移行で解消済みにしない。

新規作成は `_template.md` を使う。
