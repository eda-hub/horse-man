# 重賞年次予想ノート運用 — `docs/yosou/`

`docs/yosou/` は、JRA・海外を問わず**重賞ごとのレース固有知識を翌年へ引き継ぐための年次予想ノート**を保存する場所とする。

予想ルールそのものは `docs/manual/`、結果後の正式な回顧・検証は `docs/validation/` を正本とする。

## 1. Owner境界

| 内容 | 正本 | 役割 |
|---|---|---|
| 共通の予想・購入・回顧ルール | `docs/manual/` | Production / Shadow / betting / reviewの判断基準 |
| 重賞固有の年次知識 | `docs/yosou/<区分>/<race>.md` | 過去傾向、当年との照合、翌年課題 |
| 結果後の正式回顧・検証 | `docs/validation/` | snapshot、KPI、エラー、実購入、Shadow評価、改善候補 |
| 過年度状態 | Git履歴 | 過去年度のファイル状態 |

## 2. `docs/yosou/` に保存するもの

各重賞ファイルには、翌年の同じ重賞を予想するときに有用な**レース固有情報だけ**を残す。

- コース・距離・開催地・時期などの構造的注意点
- 過去5年等のローリング傾向
- 年齢、枠、脚質、ローテ、血統、騎手・厩舎等のレース固有傾向
- 当年予想の簡潔な要約
- **過去傾向・事前仮説から見て、当年の予想がどうだったか**
- 当年結果により、どの傾向が継続 / 弱化 / 新規候補 / 例外となったか
- **翌年に向けた予想課題**
- 翌年予想時のチェックリスト
- 傾向更新に必要な最小限の結果要約と参照資料

当年の印や着順を記す場合も、目的は**レース固有傾向との照合**に限定する。

## 3. `docs/yosou/` に保存しないもの

以下は `docs/validation/` を唯一の正本とし、重賞ファイルへ重複保存しない。

- Production / Shadow の正式な発走前snapshot全文
- 勝率・連対率・3着内率の検証表や確率校正
- 予想確信度別KPI、ROI、トリガミ率等の検証集計
- エラー分類（A〜L等）
- 反実仮想チェック
- 非劣化判定
- 検証中ルールの改善 / 中立 / 悪化判定
- 実購入の詳細、払戻、収支、回収率
- Production固定仮想資金の成績
- 改善候補の昇格 / 継続検証 / 棄却判断
- 発走前snapshot適格性、KPI適格性

必要な場合は `docs/validation/` の該当記録へリンクするだけにする。

## 4. 回顧時の固定フロー

重賞の結果確定後は、次の順序で処理する。

1. `docs/manual/50_review.md` に従い、発走前チャットsnapshotを結果を見る前の状態として固定する。
2. 結果・払戻・レース内容を確認する。
3. **正式な回顧・検証を `docs/validation/` に保存する。**
4. その後、当該 `docs/yosou/<区分>/<race>.md` を更新する。
5. yosou側では、validationの回顧を再掲せず、次だけを抽出する。
   - 過去傾向と当年予想・結果の一致 / 不一致
   - 継続 / 弱化 / 新規候補 / 例外となったレース固有傾向
   - 翌年に向けた予想課題
   - 翌年用チェックリスト
6. 共通ルールの変更可否は `docs/validation/` → `docs/manual/50_review.md` の検証手順で判断し、yosouから直接Productionルールへ昇格させない。

### 発走前snapshotがない場合

正式なProduction/Shadow回顧KPIへは算入しない。ただし、確定したレース事実を使って**レース固有の過去傾向更新だけ**をyosou側で行うことはできる。

その場合、「当年予想との比較」は作らず、結果から予想を後付け再構成しない。

## 5. 予想開始時

重賞を予想するときは、

1. `docs/manual/README.md`
2. 依頼に必要な `docs/manual/` モジュール
3. 本 `docs/yosou/README.md`
4. 区分別README（存在する場合）
5. 当該重賞ファイル（存在する場合）

の順に参照する。

yosouの過去傾向はレース固有コンテキストであり、共通Productionの能力評価を機械的に上書きしない。51B等、正式ルール上Shadowに属する傾向はProductionへ逆流させない。

## 6. 年度更新

- 原則1重賞1固定ファイルを継続利用する。
- 現行ツリーは最新年度に使える状態を保つ。
- 過年度の詳細な予想・回顧・収支を本文へ年表形式で蓄積しない。
- 過去状態はGit commit / PR / tagから参照する。
- 旧形式で回顧・検証詳細が残るファイルは、次回その重賞を更新する際に本境界へ整理する。

標準フローは、

**発走前はチャットsnapshot → 結果後はvalidationで正式回顧 → yosouで過去傾向との照合と翌年課題だけ更新**

とする。
