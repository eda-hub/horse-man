## 再計算と検査

リポジトリのルートで保存済み資料を検査する。

```bash
python3 scripts/cycle04_history.py --audit
```

新たに原記録を照合して資料を更新するときは、確認日と参照commitを明示する。確認日やcommitを自動で現在へ書き換えない。

```bash
python3 scripts/build_cycle03_review.py --write \
  --as-of-date-jst 2026-10-13 \
  --basis-commit d164153c27431e0be901e042e359fecbc568994a
```

本版の64入力hashは上記commitから取得した本文と一致している。`basis_commit` は参照履歴であり、CLIへSHAを指定する行為自体が証拠の認証になるものではない。更新時も実際のcommit内容と入力を別途照合し、理由・検証・PRへ記録する。

全日完了確認を要求する場合は次を実行する。PR80の実在回顧を取得後、両方ともexit 0を確認済み。初稿で9/27不足を検出した履歴は前commitに保持する。通常CIでも全日完了と資料の再計算一致を要求するが、性能認証や正式切替の合格ではない。

```bash
python3 scripts/check_cycle03.py --require-data --require-complete
python3 scripts/cycle04_history.py --audit
```

JSON生成は`--write`を指定した場合だけ行い、保存先は`docs/validation/reviews/`内のJSONへ限定する。原record/snapshot/receiptの出力指定と、原記録へ向くsymlinkを拒否する。入力は読み取り専用。
