# 保存状態の日本語表示（25番）

`scripts/persistence_status.py` は、Prediction・Recommendation等の保存工程に共通の日本語表示を提供する。書込、読戻し一致、対象ごとの個別完了確認の**実際の結果**だけを入力し、確認の実行・証跡の生成・適格性の認証は行わない。

| 状態 | 必要な結果 | 利用者向け説明 |
|---|---|---|
| 未試行 | 書込を試していない | 保存は未試行 |
| 書込失敗 | 書込を試し、失敗を確認した | 保存の書込に失敗 |
| 読戻し不一致 | 書込成功後、読戻した内容の不一致を確認した | 保存先から読戻した内容が一致しない |
| 本体保存済み・個別完了未確認 | 読戻し一致後、個別確認が未実施または失敗 | 本体は保存済み。個別確認の未実施と失敗を別々に説明 |
| 全完了 | 書込・読戻し一致・個別完了確認がすべて成功 | 指定対象の保存工程はすべて完了 |

書込成功後に読戻しが未実施なら、4番目の状態に分類するが「本体は書込済み」と表示し、読戻し一致済みの保存とは区別する。書込結果そのものが不明なら判定を拒否する。未実施は`null`、実際の失敗は`false`、成功は`true`。数値や文字列を成功として解釈しない。後段だけ成功している矛盾した入力も拒否する。

利用者向け出力には対象・原因・影響・次の確認を含め、内部状態コードは出さない。内部コードはAPIの`status_code`または明示指定した`--json`による監査用出力に保持する。対象は「京都10Rの予想」「推奨買い目」等の名称を指定し、内部検証IDを説明の代わりにしない。

## 呼出し方法

Pythonから`describe_persistence(target, write_attempted=..., write_succeeded=..., readback_matches=..., verification_succeeded=...)`を呼び、`render_persistence(report)`で表示する。CLIでは実際の結果を記録したJSONを`python scripts/persistence_status.py --evidence 確認結果.json`で読み込む。未実施の確認は値を補完しない。

これは保存工程の表示であり、前向きKPI・発走前適格性・Stage切替・適用Shadow・タスク全体の完了を与えない。CIの監査成功や事前宣言ファイルの存在を個別完了成功へ変換しない。26番の[個別完了確認](individual-completion.md)で既存Prediction/Recommendationの個別ゲートへ接続し、必要な確認を対象ごとに独立判定する。過去の欠落した証跡を作成して成功へ変換しない。

受入検査は`scripts/test_persistence_status.py`。必須5状態に加え、読戻し未実施、個別確認失敗、未知の書込結果、矛盾した工程、監査成功の誤用、CLI表示を検査する。既存CIの全`test_*.py`探索に含まれる。現行v1.6.1・Draft/PENDINGを保持する。
