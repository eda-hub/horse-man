## 集計原則

- ProductionとShadowを混同しない。
- 発走前に固定した値だけを比較対象とする。
- 実購入と固定仮想買い目を別帳簿にする。
- 買い判定は1レース10,000円、見送りは0円。
- 日次正式ポートフォリオは購入優先度上位最大5レース、最大50,000円。
- 見送り反実仮想10,000円は正式ROIへ含めない。
- 的中/不的中だけでなく、順位・確率・券種・資金配分・オッズ予測誤差を階層別に評価する。
- 合理的に切った馬の好走は、それだけで改善候補にしない。
- 単発結果で検証ルールを昇格させない。

## ユーザー所感・次回確認仮説

### 2026-09-13

以下は当日のユーザー所感であり、現時点では集計済みKPIや正式ルールではない。第2検証サイクルで前向きに確認する観察事項として保存する。

- ◎本命馬が1着になるレースは多かったという所感。
- 一方で、2着馬が無印だったレースが多かったという所感。
- ◎以外で印を付けた馬は、3着に入るケースが多かったという所感。

今後は、◎の1着捕捉が維持できているかだけでなく、2着馬の印外漏れと、○・▲・△・☆が2着より3着へ偏っていないかを確認する。これが継続して確認された場合は、相手馬の連対評価と3着内評価の配分、ならびに馬連・ワイド等の買い目構築への影響を検討する。単日の所感だけでは正式ルールを変更しない。

### 2026-09-16 seed再確認

ユーザー確認により、2026-09-13阪神7R・10Rはいずれも **1着馬が◎、2着馬が無印** だったことを履歴事実として追加した。

- 阪神7R: ◎⑥ジューンアゲイン 1着 / 無印⑩フレイムスター 2着
- 阪神10R: ◎⑧インヴォーグ 1着 / 無印⑤モンテシート 2着

この2例は「◎1着は取れているが、2着無印で連系を落とす」という観察に具体的に一致する。ただし発走前Git固定がないため正式KPIには算入せず、U-01/U-01Qのseedとしてのみ利用する。詳細は `records/2026-09-16_latent_upside_seed_recheck.md` を参照する。

## U-01 能力未知度 / latent-upside 事前検証

2026-09-16から、第2サイクルの補助的な前向き検証としてU-01を開始する。詳細な開始記録は `records/2026-09-16_latent_upside_precheck.md` を参照する。

- 前開催のユーザー所感、セントライト記念⑦ジャスティンシカゴの見落とし事例を仮説生成に利用する。
- 阪神7R⑩フレイムスター、阪神10R⑤モンテシートの「◎1着・無印2着」事例をseedとして利用する。
- ローズステークスのように既存印で1〜3着を捕捉できたレースを反証例として扱い、無印候補を機械的に増やさない。
- 前開催の事例はU-01の成功・失敗件数へ後付け算入しない。
- 発走前にProductionを固定した後、非価格情報だけでlatent-upside候補を固定する。
- 候補抽出では人気・オッズを使用しない。オッズは候補固定後の診断値としてのみ観測する。
- Production正式印・確率・買い目はU-01単独では変更しない。
- 比較買い目を作る場合、primary候補1頭を上限に相手列へ追加したShadow構造を保存し、追加点数と捕捉改善を測る。
- `upside_evidence=STRONG` かつ `upside_role=2着圏 / 上位全般` のprimary候補については、U-01Qとして◎-候補の馬連100円固定を別Shadowで保存する。人気・オッズは発動条件に使わない。
- U-01Qが既存Production馬連と重複する場合は追加せず `already_covered` とし、正式投資・正式ROIには算入しない。

U-01の正式な第2サイクル主KPIへの昇格は行わず、本サイクルでは補助診断として集計する。

## U-02 騎手・厩舎定量プロファイル事前検証

2026-09-19から、第2サイクルの補助的な前向き検証としてU-02を実施する。

- Production固定後に実行し、正式順位・印・確率・買い目へ逆流させない。
- 全頭で取得可能な軽量指標を試し、上位5頭・U-01 primary候補・E-04 `pace_key` 候補は細条件を追加確認する。
- 各数値に条件・集計期間・母数を付け、可能なら `YTD / LAST_4W / LAST_8W` を分けて保存する。
- 一般騎手、一般厩舎、騎手×馬、厩舎×騎手を別シグナルとして保持し、馬個体の直接実績と衝突した場合も一つの点数へ潰さない。
- 固定総合点、最低母数、最適集計期間、各指標の重みは本サイクル中に確定しない。
- 回顧では指標・期間別の追加価値、誤検出、衝突時の成否、取得率・取得コストを比較する。

## E-04 `pace_key` 展開形成馬診断

2026-09-19以降、E-04では勝率・Production順位とは別に `pace_key` を発走前固定する。低評価馬でも隊列・ペースを動かす可能性があれば対象とし、行動仮説、影響方向、証拠強度、影響シナリオを記録する。結果後は馬自身の着順ではなく、実際のペース形成への関与とシナリオ予測の改善 / 悪化で評価する。

## サイクル終了判定

サイクル終了時に各検証項目を次のいずれかへ分類する。

- 昇格
- 継続検証
- 棄却
- 判断保留

判断確定後、必要なルール変更を別PRへ反映し、その後 `docs/validation/` のサイクルファイルを削除する。過去データはGit履歴から取得する。
