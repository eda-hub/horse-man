## U-01 能力未知度 / latent-upside 事前検証

本項は第2で開始し、`50_review` 0.12.3の第3日程・選定対象にも明示継続する前向き検証運用であり、正式なProductionルールではない。恒久設計候補は `docs/jravan/13_ability_uncertainty_review.md` を参照する。

第2では2026-09-16以降の対象、第3では選定候補の最終予想で、Productionの順位・印・確率を固定した後、結果確認前かつ発走前に全出走馬を軽量スキャンする。目的は、無印馬について「中心能力が低い」と「中心能力の推定幅が大きい」を分離して事前保存することである。

最低限、候補馬について次を保存する。

- Productionの印・基準順位
- `evidence_coverage`: LOW / MEDIUM / HIGH
- `ability_uncertainty`: LOW / MEDIUM / HIGH
- `upside_evidence`: NONE / WEAK / MODERATE / STRONG
- 上振れ根拠の要約
- `latent_upside_candidate`: true / false
- 候補なら想定役割：2着圏 / 3着圏 / 上位全般

候補抽出では**人気・単勝オッズ・組み合わせオッズを使用しない**。まず非価格情報だけで候補を固定し、その後に市場価格を記録する場合も、候補選定の根拠へ逆流させない。これにより「潜在上振れ候補は実際に高オッズになりやすいか」自体を結果と独立して観察できる。

Productionの正式印・正式買い目はU-01だけを理由に変更しない。比較買い目を作る場合は、買い目点数の無制限な膨張を避けるため、事前証拠が最も強い `primary latent-upside candidate` 1頭を上限として、Productionの中心軸を変えず相手列へ追加したShadow構造を保存する。オッズ不足を理由に候補自体を消さない。

回顧では、無印好走馬を発走前snapshotだけから `SIGNAL_MISSED / UNCERTAINTY_UNDERMODELED / RATIONAL_EXCLUSION / POST_HOC_ONLY` に分類する。結果後に候補を新設して適格化しない。

本検証の開始根拠・前開催からの仮説は `records/2026-09-16_latent_upside_precheck.md` に保存する。前開催の事例は仮説生成にだけ使用し、U-01の前向き成績には算入しない。

## U-02 騎手・厩舎定量プロファイル事前検証

本項は第2で開始し、`50_review` 0.12.3の第3日程・選定対象にも明示継続する補助的な前向き検証であり、正式なProductionルール、固定スコア、加減点表ではない。目的は、現行ルール15 / 15.1 / 51-8 / 51-8.1で確認対象となっている騎手・厩舎情報について、**安定取得できる範囲、適切な集計期間、母数、予測への追加価値、取得コスト**を前向きに測ることである。

### 実行原則

- Production順位・印・確率を固定した後にU-02を実行し、同一レースのProductionへ逆流させない。
- 全出走馬について取得コストの低い共通項目を可能な範囲で揃える。細条件はProduction上位5頭、U-01 primary候補、E-04 `pace_key` 候補を優先してよい。
- 各集計値には**対象条件、集計期間、母数**を必ず対応付ける。期間不明・母数不明の率を比較根拠にしない。
- 取得不能項目を推測・補完せず `UNAVAILABLE` とする。
- 固定総合点、最低母数、最適集計期間、各指標の重みは本サイクル中に確定しない。

### 取得候補

可能な範囲で、当年、直近4週、直近8週、当該競馬場、芝 / ダート・距離帯、重賞、騎手×当該馬、厩舎×今回騎手等について、出走数・勝率・連対率・複勝率を取得する。単勝回収率・複勝回収率や人気・オッズ補正は取得できる場合の追加診断とし、必須化しない。

期間を比較できる場合は同じ指標を `YTD / LAST_4W / LAST_8W` 等のラベル付きで保持し、後から都合のよい期間だけを選ばない。

### シグナルを潰さず保持する

馬個体の直接実績と一般的な騎手・厩舎統計が衝突する場合を検証できるよう、少なくとも次を分離して保存する。

- `jockey_general_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `trainer_general_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `jockey_horse_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `trainer_jockey_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `jockey_evidence_coverage`: LOW / MEDIUM / HIGH
- `trainer_evidence_coverage`: LOW / MEDIUM / HIGH
- 各シグナルの証拠強度: WEAK / MODERATE / STRONG
- `horse_direct_evidence_alignment`: SUPPORT / CONFLICT / NONE
- `context_connection`: 今回の展開・位置取り・仕上げ・ローテとの接続理由
- `shadow_direction`: UP / HOLD / DOWN

`shadow_direction` は成分を固定重みで合算した点数ではない。今回の展開・位置取り・仕上げ・ローテとの接続を文章で確認したうえで、診断上の方向だけを保存する。

- 20レース未満では精度差を方向確認に留め、優劣を確定しない。
- 本サイクルだけではProductionへの正式昇格を行わない。終了時は **継続検証 / 棄却 / 判断保留** のいずれかを基本判定とする。

精度の暫定非劣化目安は、三者共通集合で平均Brier ScoreがP比 `+0.01` 以内、かつ◎3着内率・上位3頭勝ち馬捕捉率がP比 `-5ポイント` を超えて悪化しないこととする。改善候補は平均Brier ScoreがP比 `-0.01` 以上改善する、または順位指標がP比 `+5ポイント` 以上改善し、他の主要指標が非劣化範囲内にある場合とする。少数標本ではこの閾値を昇格根拠に使わない。

1. 発走前に予想・選別したレース総数を `prediction_scope_count` として確定し、同時に期待する `race_id` 集合を固定する。
2. 日別record内の**scope台帳は1レース1行**とし、scope台帳の `race_id` は一意であることを確認する。件数が同じでも「1R重複＋別1R欠落」は `REVIEW_SCOPE_MISMATCH` とする。

6. **証跡取得成功と回顧完了を分離する。** `GIT_SNAPSHOT_VERIFIED` ではsnapshot本体とpersistence receiptの対応を要求する。一方、他状態でGit証跡が欠けても、欠測理由・利用できた代替証跡・KPI別の適格/不適格判定が全scopeレースで確定していれば、その欠測だけを理由に回顧全体を未完了のままにしない。未試行・実行不能・成否不明を保存失敗へ変換しない。
7. 個別最終予想、購入候補、見送りを含め、scope台帳の全レースに回顧recordが存在することを確認する。scope台帳自体の件数・集合が未確定なら `REVIEW_SCOPE_MISMATCH` とし、回顧を完了扱いにしない。
8. 実購入を計上する場合は、購入明細の各金額を合計し、記録した実購入総額と一致することを確認する。購入意思だけ、金額不一致、明細欠落は実購入確定へ進めない。

### 記録範囲と採点可能範囲の照合

件数一致は記録対象の網羅を確認する条件であり、分析可能性を保証しない。日別recordには次を別々に記載する。

- 事前予想・選別対象件数（prediction_scope_count）
- 対象の存在を記録した件数
- 発走前の詳細を回顧で参照できる件数
- 予想精度 / 購入・ROI / 各Shadowについて、対象件数・適格件数・除外件数と理由
- 日次選別リフト等の採点可否と、比較対象側の不足項目
- scope台帳の期待race_id集合 / record集合 / scope台帳の重複件数
- snapshot履歴のsnapshot_id件数 / snapshot_id重複件数 / previous_snapshot_ref整合
- 各scopeレースの発走前証跡状態・代替証跡・KPI別適格性
- `GIT_SNAPSHOT_VERIFIED` としたsnapshot参照の読戻し結果
- 実購入を計上する場合の購入明細合計 / 記録総額 / 差額

全体選別は、上位候補以外も各レース1行で残す。「上位5外」を「見送り」と読み替えず、区分不明は不明とする。適格件数と除外件数はKPIごとの同一対象集合で照合し、複数の除外理由があってもレース数を重複加算しない。各Shadowの非該当は適用対象から分ける。対象該当性自体が不明なら、非該当にせず要確認として残す。

元の予想チャットに発走前の実記録が残っている場合は、該当メッセージ・時刻・内容を照合して転記漏れを訂正できる。結果後に新しいID・印・確率・Shadow・変更理由を作ることとは区別する。既存の不適格判定を変更できるのは、必要条件が当時すでに固定されていたことを確認した場合だけで、変更前後と出典を残す。
