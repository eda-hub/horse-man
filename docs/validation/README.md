4. **新仮説の追加価値**：発走前比較が成立した対象だけを評価する。E-13は従来どおりProduction・既存必須Shadow完了後、追加3分上限とする。

上記は検証を成立させるための重点順であり、既存モード5の実施対象を任意に減らす指示ではない。工程負荷も観察し、時間不足・入力不足・工程失念を区別する。原因の記録がなければ「原因不明」とし、未実行を取得失敗へ置き換えない。

### 診断観点

- **候補抽出**：上位k頭の捕捉数とともに、選択頭数k / 出走頭数を残す。「印内にいた」だけで抽出能力が十分と確定しない。
- **順位**：上位馬間の比較根拠と初期→最終の変更を確認する。◎不勝だけで順位付けミスと断定しない。
- **確率**：発走前の中心値・レンジと実績の整合を蓄積する。少数例から確率差を人為的に広げず、単日の不的中だけで過大評価と確定しない。
- **馬券への接続**：僅差の能力評価を、購入段階で圧倒的な軸として扱っていなかったかを確認する。順位・確率の問題と分離し、根拠不足なら判定保留とする。
- **48.2監査**：馬依存率・依存額、券種成立に必要な確率とレンジ下側、軸が崩れるシナリオ、使用価格、監査後の判断（維持 / 配分変更 / 総投資削減 / 見送り）と根拠を記録する。事前記録がなければ実施済みにしない。70%・100%等を新たな一律禁止閾値にしない。
- **資金帳簿**：48.2の判断は実運用案と固定仮想案で区別する。固定仮想資金の条件は30_betting 0.20と本書を維持し、実購入の減額を固定10,000円案の成績へ混ぜない。
- **確信度**：予想確信度と購入確信度を別尺度のまま評価する。予想B・購入A帯だけで矛盾とせず、保守側確率・価格でも購入判断を説明できたか確認する。
- **差分更新**：変更馬・方向・非価格理由・証拠強度・情報時刻と、確信度変更理由を発走前記録へ対応付ける。手順違反と、結果上の改善 / 悪化は別に採点する。
- **展開・馬場・個体適性**：E-04は隊列・ペース形成、20_conditional 0.5は当日馬場と位置取りの有利不利、E-09は馬個体の条件・ローテ適合として別採点する。逃げ馬の勝利だけで3項目を一括成功にしない。E-04は当該馬の着順だけでなく実際の展開形成への関与を見る。
- **証拠優先順位**：直接実走を優先する現行ルールの適用監査と、E-13のP/A/B比較を分ける。未固定Shadowを結果後に作って追加価値を主張しない。

## U-01 能力未知度 / latent-upside 事前検証

本項は第2サイクルだけの前向き検証運用であり、正式なProductionルールではない。恒久設計候補は `docs/jravan/13_ability_uncertainty_review.md` を参照する。

2026-09-16以降、本サイクルでProduction最終予想を保存する対象レースでは、Productionの順位・印・確率を固定した後、結果確認前かつ発走前に全出走馬を軽量スキャンする。目的は、無印馬について「中心能力が低い」と「中心能力の推定幅が大きい」を分離して事前保存することである。

最低限、候補馬について次を保存する。

- Productionの印・基準順位
- `evidence_coverage`: LOW / MEDIUM / HIGH
- `ability_uncertainty`: LOW / MEDIUM / HIGH
- `upside_evidence`: NONE / WEAK / MODERATE / STRONG
- 上振れ根拠の要約
- `latent_upside_candidate`: true / false
- 候補なら想定役割：2着圏 / 3着圏 / 上位全般

候補抽出では**人気・単勝オッズ・組み合わせオッズを使用しない**。まず非価格情報だけで候補を固定し、その後に市場価格を記録する場合も、候補選定の根拠へ逆流させない。これにより「潜在上振れ候補は実際に高オッズになりやすいか」自体を結果と独立して観察できる。

Productionの正式印・正式買い目はU-01だけを理由に変更しない。比較買い目を作る場合は、買い目点数の無制限な膨張を避けるため、事前証拠が最も強い `primary latent-upside candidate` 1頭を上限として、Productionの中心軸を変えず相手列へ追加したShadow構造を保存する。オッズ不足を理由に候補自体を消さない。

回顧では、無印好走馬を発走前snapshotだけから `SIGNAL_MISSED / UNCERTAINTY_UNDERMODELED / RATIONAL_EXCLUSION / POST_HOC_ONLY` に分類する。結果後に候補を新設して適格化しない。

本検証の開始根拠・前開催からの仮説は `records/2026-09-16_latent_upside_precheck.md` に保存する。前開催の事例は仮説生成にだけ使用し、U-01の前向き成績には算入しない。

## U-02 騎手・厩舎定量プロファイル事前検証

本項は第2サイクルだけの補助的な前向き検証であり、正式なProductionルール、固定スコア、加減点表ではない。目的は、現行ルール15 / 15.1 / 51-8 / 51-8.1で確認対象となっている騎手・厩舎情報について、**安定取得できる範囲、適切な集計期間、母数、予測への追加価値、取得コスト**を前向きに測ることである。

### 実行原則

- Production順位・印・確率を固定した後にU-02を実行し、同一レースのProductionへ逆流させない。
- 全出走馬について取得コストの低い共通項目を可能な範囲で揃える。細条件はProduction上位5頭、U-01 primary候補、E-04 `pace_key` 候補を優先してよい。
- 各集計値には**対象条件、集計期間、母数**を必ず対応付ける。期間不明・母数不明の率を比較根拠にしない。
- 取得不能項目を推測・補完せず `UNAVAILABLE` とする。
- 固定総合点、最低母数、最適集計期間、各指標の重みは本サイクル中に確定しない。

### 取得候補

可能な範囲で、当年、直近4週、直近8週、当該競馬場、芝 / ダート・距離帯、重賞、騎手×当該馬、厩舎×今回騎手等について、出走数・勝率・連対率・複勝率を取得する。単勝回収率・複勝回収率や人気・オッズ補正は取得できる場合の追加診断とし、必須化しない。

期間を比較できる場合は同じ指標を `YTD / LAST_4W / LAST_8W` 等のラベル付きで保持し、後から都合のよい期間だけを選ばない。

### シグナルを潰さず保持する

馬個体の直接実績と一般的な騎手・厩舎統計が衝突する場合を検証できるよう、少なくとも次を分離して保存する。

- `jockey_general_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `trainer_general_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `jockey_horse_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `trainer_jockey_signal`: POSITIVE / NEUTRAL / NEGATIVE / UNKNOWN
- `jockey_evidence_coverage`: LOW / MEDIUM / HIGH
- `trainer_evidence_coverage`: LOW / MEDIUM / HIGH
- 各シグナルの証拠強度: WEAK / MODERATE / STRONG
- `horse_direct_evidence_alignment`: SUPPORT / CONFLICT / NONE
- `context_connection`: 今回の展開・位置取り・仕上げ・ローテとの接続理由
- `shadow_direction`: UP / HOLD / DOWN

`shadow_direction` は成分を固定重みで合算した点数ではない。今回の展開・位置取り・仕上げ・ローテとの接続を文章で確認したうえで、診断上の方向だけを保存する。

### 回顧・評価

結果後は、各成分シグナルと集計期間を分けて、好走率・誤検出、Production上位馬間の順序判断への追加価値、無印・低評価馬の事前捕捉、馬個体実績との衝突時の成否、取得率・取得コストを比較する。結果を見てから条件や集計期間を追加して適格化しない。

サイクル終了時に、指標ごと・期間ごとに **採用 / 継続検証 / 棄却 / 判断保留** を判定する。

## E-13 評価根拠優先順位比較 — 第2サイクル終盤パイロット

2026-09-19 17:43 JSTから、第2サイクルの残り期間でE-13を前向きに追加する。詳細な開始条件は `records/2026-09-19_e13_evaluation_priority_precheck.md` を正本とする。

### 対象

次の両方を満たすレースを対象候補とする。

- 2026-09-19 17:43 JST以降、2026-09-22のサイクル終了までに発走前Productionを新規固定または正式更新する。
- 現行モード5の自動実行対象、またはユーザーが個別にProduction予想を依頼したレース。

開始時刻より前に発走済み・結果確認済み・A/Bを未固定のレースは遡及算入しない。

### 三者比較

- **P**：現行Production。E-13のために再生成しない。
- **A**：個体実走優先。
- **B**：血統優先。

P/A/Bは同じ `race_evidence_bundle` と情報締切を使い、A/Bのために同じ事実を別々に再取得しない。A/Bの片側だけに追加情報が入ったレースは三者同一入力比較から除外する。

### 実行ガード

- Productionと既存必須Shadowを先に完了する。
- E-13追加処理は1レース最大3分。
- 上限到達は `E13_TIME_LIMIT`、必要入力不足は `E13_INPUT_INCOMPLETE` とする。
- E-13未完了でもProductionと既存Shadowの適格性は失わせない。
- 発走前はチャットsnapshotへ固定し、Git記録は結果後の回顧で一括する。

### パイロット判定

- **8レース以上**：実行完了率・欠測・追加時間等の運用評価を行う。
- **20レース以上**：P/A/BのBrier Score差・順位指標を参考比較できる。
- 20レース未満では精度差を方向確認に留め、優劣を確定しない。
- 本サイクルだけではProductionへの正式昇格を行わない。終了時は **継続検証 / 棄却 / 判断保留** のいずれかを基本判定とする。

精度の暫定非劣化目安は、三者共通集合で平均Brier ScoreがP比 `+0.01` 以内、かつ◎3着内率・上位3頭勝ち馬捕捉率がP比 `-5ポイント` を超えて悪化しないこととする。改善候補は平均Brier ScoreがP比 `-0.01` 以上改善する、または順位指標がP比 `+5ポイント` 以上改善し、他の主要指標が非劣化範囲内にある場合とする。少数標本ではこの閾値を昇格根拠に使わない。

## 前向き検証レースの事前固定

結果後の後知恵を防ぐため、KPIごとに**発走前に保存されていた項目だけ**を使用する。結果後に欠けた値を再構成して適格化しない。

### 予想精度KPIの適格条件

正式な予想精度サンプルには、発走前に最低限次を固定する。

- `baseline_forecast_id`
- レース識別情報・情報取得時刻
- Production順位・印・確率
- 予想確信度
- 当日予想では当日馬体重の取得状態

これらが揃っていれば、購入側の記録欠落だけを理由に◎勝率・上位3頭捕捉率・確率校正等の**予想精度サンプルまで捨てない**。

### 購入・ROI KPIの追加適格条件

購入・ROI・オッズ予測KPIへ算入するには、上記に加えて発走前に次を固定する。

- 買い / 見送り判定
- 使用オッズと取得時刻
- 買い判定時の10,000円固定仮想買い目・資金配分
- オッズ予測KPIを評価する場合は予測最終オッズ等の必要値

購入側だけ不足した場合は、`PREDICTION_ELIGIBLE / BETTING_INELIGIBLE` のようにKPI別に適格性を分ける。Production予想自体が発走前に固定されていない場合は予想精度KPIからも除外する。

### 発走前回答の工程状態

既存の検証記録用サマリーに、次の状態を簡潔に併記する。本文にある数値を重複転記する必要はなく、同一回答内の該当表・時刻を参照してよい。

| 確認対象 | 記録する状態・根拠 |
|---|---|
| Production | 基準予想ID、固定時刻、順位・確率・確信度・当日馬体重取得状態の所在 |
| 市場照会前の能力評価 | オッズ照会前snapshotの所在。追跡できなければ独立性未確認 |
| 順位・確信度変更 | 変更なし、または変更対象・理由・証拠・時刻の所在 |
| 購入案と監査 | 使用価格・時刻・固定仮想案、単勝対象と48.2監査結果の所在 |
| 各Shadow | 50_review 0.12.2と本書に基づく適用対象ごとに、完了 / 非該当 / 未完了と根拠 |

「完了」は必要な出力を発走前に固定した場合だけとする。「非該当」は適用条件を示し、時間が足りなかった工程には使わない。「未完了」は時間不足 / 入力不足 / 工程失念 / 原因不明を分け、既存の詳細理由コードがあれば併記する。計測できる工程時間を残し、計測していない時間を推定で埋めない。

締切時はmanual READMEのfail-soft原則に従い、利用可能なProductionを発走前に提示し、検証工程の未完了を明示する。未完了工程を完了扱いにせず、Productionと各Shadowの適格性は独立判定する。発走前の記録目的のGit書き込みは行わない。

## 回顧時の記録完了ゲート

Gitへの永続記録は結果確定後の回顧時に行う。発走前はチャットsnapshotを正とし、記録目的だけのGit書き込みは行わない。

モード2等で複数レースを事前予想した日は、回顧終了前に次を確認する。

1. 発走前に予想・選別したレース総数を `prediction_scope_count` として確定する。
2. 個別最終予想、購入候補、見送りを含め、事前予想した全レースが日別recordに1行以上存在することを確認する。
3. `prediction_scope_count` と記録済み件数が一致しない場合、回顧を完了扱いにしない。
4. チャットsnapshotの詳細を回顧時に復元できないレースは、結果から印を作り直さず `REVIEW_INPUT_SNAPSHOT_DETAIL_UNAVAILABLE` として対象だった事実だけを保存する。
5. 発走前Git未記録そのものは欠陥としない。問題は、結果後回顧で追跡可能な発走前snapshotを永続記録へ転記できないこと、または転記対象を漏らすことである。

### 記録範囲と採点可能範囲の照合

件数一致は記録対象の網羅を確認する条件であり、分析可能性を保証しない。日別recordには次を別々に記載する。

- 事前予想・選別対象件数（prediction_scope_count）
- 対象の存在を記録した件数
- 発走前の詳細を回顧で参照できる件数
- 予想精度 / 購入・ROI / 各Shadowについて、対象件数・適格件数・除外件数と理由
- 日次選別リフト等の採点可否と、比較対象側の不足項目

全体選別は、上位候補以外も各レース1行で残す。「上位5外」を「見送り」と読み替えず、区分不明は不明とする。適格件数と除外件数はKPIごとの同一対象集合で照合し、複数の除外理由があってもレース数を重複加算しない。各Shadowの非該当は適用対象から分ける。対象該当性自体が不明なら、非該当にせず要確認として残す。

元の予想チャットに発走前の実記録が残っている場合は、該当メッセージ・時刻・内容を照合して転記漏れを訂正できる。結果後に新しいID・印・確率・Shadow・変更理由を作ることとは区別する。既存の不適格判定を変更できるのは、必要条件が当時すでに固定されていたことを確認した場合だけで、変更前後と出典を残す。

## 保存形式

- サイクル集計：`cycle_02.md`
- 必要な日別・レース別記録：`records/YYYY-MM-DD.md` または `records/<race-id>.md`

同一内容を `40_shadow.md` や `docs/yosou/` の個別重賞ファイルへ重複保存しない。**正式回顧の詳細はvalidation側へ保持する。** `docs/yosou/` には、過去傾向から見た当年予想・結果の照合、傾向更新、翌年予想課題だけを抽出して残す。保存境界は `docs/yosou/README.md` と `docs/manual/50_review.md` 0.7.1.2 を参照する。
