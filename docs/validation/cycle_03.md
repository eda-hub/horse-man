## 1. 範囲と分母

7日×2場×12Rなら開催レース数の計画上限は**168R**。これは利用者指定日程に基づく仮定であり、公式番組で確定する。168Rを有効サンプル数・予想実行件数・検証工程の実行件数とはしない。延期・中止・R数変更は元予定と変更後を記録する。

初回予想では依頼範囲を評価し、検証用・購入用・両方の候補へ絞る。最終予想はその選定集合だけを対象とする。初回予想数と最終予想数の不一致は正常であり、件数一致を要求しない。対象集合の管理は下記に従う。

### 初回・選定・最終・回顧の集合を分離する

- `initial_scope`：初回予想を行った全race_id。
- `validation_candidates`：検証用に選んだrace_id。
- `purchase_candidates`：購入用に選んだrace_id。
- `selected_final_scope = validation_candidates ∪ purchase_candidates`：最終予想・買い目作成の対象。両方に該当しても重複計上しない。
- `final_completed_scope`：実際に最終予想・必要な買い目出力を完了したrace_id。
- `review_scope`：初回scope全件。最終対象外の初回予想も、その記録で評価可能な範囲を回顧する。

最終の漏れは `selected_final_scope − final_completed_scope` で確認する。候補外の `initial_scope − selected_final_scope` は「最終対象外（選別による正常な省略）」とし、最終未実施の欠測・運用失敗・最終完了率の分母に含めない。初回予想の精度評価・回顧対象からは消さない。最終対象でなければ最終段階のKPIは対象外であり、必要記録欠落による不適格と区別する。

件数が同じでも別レースへの置換は合格にしない。利用者の追加選定・個別最終依頼がある場合は、そのrace_idと選定理由・時刻を台帳へ明示追加したうえで対象集合を更新する。重賞等の既存条件は選定時の確認と、選定されたレースに適用する検証項目の判定に使い、候補外を無断で最終対象へ広げない。実装時はこの利用者指定の対象境界をOwnerへ整合反映する。

**例：初回24R、検証用4R、購入用3R、両方に該当2Rなら、最終対象は5R。5Rの最終予想と買い目が完了すれば最終対象の完了率は5/5であり、5/24ではない。残り19Rは正常な最終対象外。** 回顧は24Rを台帳で照合し、初回評価と候補5Rの詳細評価を分ける。

検証用のみのレースにも検証用買い目を作成・発走前固定する。正式購入推奨、固定仮想資金による正式ROI、検証用/見送り反実仮想、実購入は区別し、検証用の案を自動的に正式購入ROIへ混ぜない。最終で見送りになった場合は正式投資0円と検証用の案を区別する。入力・監査不足で買い目を作れない場合は推測で作らず、当該候補の買い目未完了と理由を明示する。

海外レースが別途依頼された場合は国内開催168Rとは別枠で管理する。実購入・口座・自動投票を検証成立の条件にしない。

## 2. 初回予想・候補の最終予想・回顧に検証取得を組み込む

本計画の「自動」は、**初回予想、検証候補/購入候補レースの最終予想、回顧を実行した際に、検証のための追加指示なしで必要情報の取得・比較・保存を行うこと**を指す。通常の予想依頼・最終予想依頼・回顧依頼を実行契機とする。定時スケジューラやタスクIDの登録を前提条件にしない。

### 3段階の取得・記録

| 段階 | 対象 | 取得・確定する内容 | 次段階へ渡すもの |
|---|---|---|---|
| 初回予想 | 依頼範囲の全レース | レース識別・発走時刻・出走情報、過去走/血統/コース等の静的根拠と当日時点の動的情報。市場評価前のProduction順位・印・確率・確信度・主要根拠を固定。その後に候補区分・選定理由と各検証項目の適用条件を判定し、その時点で実施可能な比較を保存 | baseline_forecast_id、snapshot/receipt、元branch、情報源/取得時刻/対象範囲、検証候補と購入候補の集合、未取得項目・取得予定段階 |
| 最終予想 | **検証候補または購入候補に一度でも挙がったレース**。双方の和集合だけを対象とする。両方に該当するRは1件とし、候補外を重賞等の属性だけで最終対象に追加しない | 初回記録を回収し、取消/騎手変更/馬場/当日馬体重等を更新。強い非価格情報による正式差分と理由を記録。Production固定後に該当Shadowを実行し、市場価格・時刻・E-08、購入前監査、買い/見送り、購入用の正式固定仮想案または検証用買い目、該当比較買い目を発走前に固定・保存・読戻し | 初回→最終差分、各比較の入力/固定時刻、KPI別必須項目、未完了理由、本体/receipt参照。見送りになっても検証記録を残す |
| 回顧 | 初回予想scope全件。候補外・見送り・最終未実施も含む | 発走前記録を取得・照合し、確定着順・払戻・確定最終オッズ、検証に必要な通過順/ラップ等を取得。確認済み実購入は別帳簿で照合。Production/各Shadowの比較、誤差分類、KPI別適格性、日別記録とサイクル集計を更新 | scope一致、KPI別の対象/適格/不適格/保留、運用漏れ、改善/悪化/中立、次回繰越 |

情報取得だけで完了にせず、検証に必要な比較出力と発走前固定までを工程に含める。静的情報は出所・時点・対象範囲を確認して再利用し、動的情報は必要時点に更新する。事実データを共有しても、Shadowの判断をProductionへ戻さない。初回で適用条件が不明なら「要確認」として最終へ引き継ぎ、非該当扱いにしない。

### 対象と取得時点の取りこぼし防止

- 検証候補と購入候補は別フラグで保持し、購入優先上位5だけに検証範囲を縮めない。検証候補であることは購入を意味しない。
- 初回選定・その後の追加選定の履歴を残す。最終で見送りや候補降格になっても、そのレースの最終検証対象履歴を削除しない。
- 各検証項目に「初回取得済み」「最終で更新/取得」「回顧で取得」を割り当てる。発走前に必要な根拠・確率・候補・Shadow・監査を、回顧で取得すればよい項目へ移さない。
- 最終予想実行時に初回の候補台帳と未取得一覧を照合し、対象の取得・比較を追加指示なしで行う。初回記録が回収不能なら記憶から再生成しない。
- 選定集合に属するのに最終予想の依頼・実行自体がなかったレースだけを、候補台帳に「最終未実施」として残し、回顧時に欠測を判定する。依頼なしでバックグラウンド実行されたとは扱わない。実行されたのに取得工程を省略した場合は「工程失念」等と分ける。
- 回顧で発走前の不足値を新設しない。結果後に取得した新情報は結果後診断として分離し、当時の前向き比較を適格化しない。

### 工程への適用と完了条件

実装時は、manual READMEの依頼別入口、00_coreの初回/最終・保存/引継ぎ、50_reviewの検証/回顧へ3段階の取得契約を接続する。40_shadowおよびU系の適用条件・必須出力はそれぞれのOwnerを参照し、同じ定義を複製しない。第3サイクルでは検証候補の最終予想も対象に含むことを明示登録する。

担当は各予想・回顧を実行するアシスタントとする。各回答前に、その段階の必要項目・比較・保存/読戻しの状態を照合し、未完了なら対象・不足・理由・影響を当該チャットで報告する。状態表示だけでは正常完了にしない。

### 実行順と障害時の扱い

予想ShadowはProduction予想固定後、買い目ShadowはProduction買い目固定後とし、00_core / 50_reviewの工程順に従う。E-13は既存必須Shadow完了後、追加3分上限を継続登録する。

- 本体保存先は書込要求前の時刻で決め、最終時刻適格性は本体読戻し後のreceiptで判定する。
- 本体 `PERSIST_VERIFIED`、receipt `RECEIPT_VERIFIED`、receipt上 `PRE_RACE_ELIGIBLE` に加え、各KPI固有の内容条件を確認する。
- 読戻しが発走予定時刻以後なら `READBACK_AFTER_POST_INELIGIBLE`。nullのまま時刻比較しない。receipt復旧で本体読戻し時刻を推測しない。
- 保存失敗でも利用可能な予想回答は現行fail-softで返し、該当KPIだけ不適格/保留にする。正確なfail-softは障害処理の合格であって、発走前保存成功ではない。
- 実レースに意図的な障害・遅延・衝突を加えない。異常系は専用試験branch・架空IDで行い、実績と模擬を別集計する。
- 実I/Oできない条件はTABLETOP確認に留め、実行合格へ読み替えない。別コンテキスト試験ができなければ同じ実行での再読込だけで代用合格にしない。

## 6. 運用KPIと受入ゲート

成功率には件数を併記する。各KPIの対象集合を先に固定し、未実行・不適格を分母から消して高く見せない。非該当は条件根拠がある場合だけ分離する。

| 指標 | 定義 | 第3サイクルの目標 |
|---|---|---|
| 段階別取得着手率 | 必要取得へ着手したレース×段階数 / 実行された依頼で取得対象となるレース×段階数 | 初回/最終/回顧ごとに100%。未依頼の最終・回顧は未実施台帳で別管理 |
| 必須工程状態記録率 | 完了/根拠付き非該当/理由付き未完了を確定した工程数 / 判定対象工程数 | 100% |
| 必須Shadow実行完了率 | 発走前の内容・本体・receipt確認済み数 / 適用対象数（項目別） | 100%。未完了理由を併記、状態記録率とは別指標 |
| 発走前保存成立率 | 内容と保存要件を満たす固定成果物数 / 保存対象の固定成果物数 | 100%。Production/Betting/Shadowを分離 |
| 終端までの無介入成立率 | 初回・最終・回顧の必要工程を各段階の通常依頼だけで正常完了したR / 一巡対象R（選定した検証用・購入用の和集合） | 100%を目標。0件分母は評価不能 |
| KPI適格率 | KPI適格R / 各KPIの事前対象R | 件数と不足理由を表示。見送り等の対象条件は既存Ownerに従う |
| 集計整合率 | scope・日別・サイクルの照合が済んだ日数 / 対象日数 | 100% |
| 保存/比較所要時間 | 実測の中央値・最大・p95（小標本では参考） | E-13上限遵守。全体は発走前完了、無制限再試行0 |
| 利用者介入 | 督促・時刻訂正・保存指示・手動復旧の件数/対象R | 0。通常の初回予想/最終予想/回顧依頼・購入意思表明は障害介入に含めない |

一巡対象Rのうち最終・回顧が未依頼/未実施のものも分母から消さず、未実施として内訳表示する。段階別着手率だけで一巡成立を主張しない。

「正常完了」は必要工程が実施され、必要内容が揃い、保存・回顧・集計を終えた場合に限る。入力欠測や保存障害を正しく記録した実行は、安全な障害処理として別評価する。

- **G0（開始前）**: 第3適用登録、3段階の取得契約・候補台帳・未取得引継ぎの確認、専用試験で重大経路の確認。未試験項目は明記。
- **G1（9/27後）**: 2開催日連続で予定scopeのP0工程を追加督促なく完了。誤適格化・履歴破壊・時刻誤認・無言再生成・Shadow逆流は0件。手動救済日は無介入成功に数えない。
- **G2（10/4後）**: 開催場切替後もP0再現、P1の適格ペアを蓄積。各仮説の対象数/完了数/不足理由を確認。
- **G3（終了時）**: 7日分のscopeと集計を閉じ、3日連続開催での再現を判定。未達項目は失敗/未検証のまま繰越し、合格へ丸めない。

G1未達でも日程を消したり通常予想を一律停止したりしない。現行安全策で継続し、運用欠陥の是正・再試験を優先する。必須ShadowをP2扱いに変更して省略しない。

## 7. 性能検証の進め方と繰越判定

運用合格と性能合格は独立して記録する。全体P0未達の日でも、そのレースで適格性を証明できたProduction/Shadowペアは捨てず、実行品質を併記して蓄積する。

1. 候補抽出→順位→確率→選別/価格→券種/配分を分けて採点する。
2. ProductionとShadowの比較は同じレース・情報締切・共通入力の適格ペア集合で行い、片方の欠落を補完しない。
3. 全体だけでなく中山/阪神と東京/京都、芝/ダート、午前/午後、確信度別の件数を示す。少数条件で優劣を確定しない。
4. 日次上位5ROIは事前の購入優先順位・買い/見送り・必要固定案が揃った日だけ正式採点する。上位5外と見送りを区別する。
5. 51B/E-09/E-10/E-11/E-12/E-08/E-04/U系等は、総括の繰越台帳と現行Ownerの出力を対応付ける。未適用・非該当・未完了・適格比較0を区別する。

7. 第2/第3のデータを無条件に合算しない。同じルール・条件・入力・適格契約の比較可能性を示せる場合のみ、サイクル別内訳を残して補助集計する。
8. その他仮説に新しい一律最低件数を作らない。既存昇格審査を満たさず、適格数・条件幅・改善/悪化比較が不足すれば継続検証または判断保留とする。効果不足による棄却と、未実行による保留を区別する。
