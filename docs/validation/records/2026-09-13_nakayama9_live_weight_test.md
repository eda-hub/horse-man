# 2026-09-13 中山9R 当日馬体重ライブ取得テスト

## 対象
- 開催: 2026-09-13 4回中山4日
- レース: 9R 習志野特別
- 発走: 14:25
- テスト時刻: 14:17〜14:18 JST
- 出走頭数: 11頭

## テスト目的
`docs/manual/README.md` の「JRA当日馬体重取得契約」が、チャット/Web実行でも当日馬体重の取得試行を起動し、取得不能時に正しく障害分類できるかを確認する。

## 実行結果
JRA公式の対象レース・発走時刻・11頭の出走構成は確認できた。一方、この実行環境で利用可能なWeb取得経路ではJRA公式・netkeiba・競馬ラボ等の検索結果が検索キャッシュ/静的取得を返し、当日馬体重欄は未反映または空欄だった。

発走8分前であるにもかかわらずライブページ状態へ直接到達できず、当日馬体重11頭分の取得は成功しなかった。

## 判定
- acquisition status: `SOURCE_ERROR`
- data readiness: `DEGRADED`
- `MISSING` や「未発表」とは判定しない。
- 検索キャッシュの空欄をJRA側未発表の根拠にしない。
- 前走馬体重・調教後馬体重で補完しない。

## 原因
今回の失敗は馬体重取得契約を起動しなかったことではなく、チャット側のネイティブWeb検索がライブ動的ページではなく検索キャッシュを返し、JavaScript描画後または最新サーバー状態を検証できなかったことによる実行環境側の取得障害と判断する。

## 改善
- `.agents/skills/horse-racing-forecast/SKILL.md` に、検索キャッシュしか取得できずライブ状態を検証できない場合は `SOURCE_ERROR` とする規約を追加する。
- ライブ当日値の取得では、利用可能ならJavaScript描画後のページを読めるライブブラウザ経路、またはローカルJV-Link/保存済み `0B11` を検索キャッシュより優先する。
- ローカルシステム実装後は、チャット直前取得に依存せず `JVEvtWeight -> 0B11` で発表時に永続化し、FINAL時は保存済みsnapshotを参照する。

## 受入確認
将来の再テストでは、同様に発走直前の対象レースを指定し、現出走馬全頭について当日馬体重・増減を `READY` として返せることを合格条件とする。検索キャッシュしかない環境では成功扱いにしない。
