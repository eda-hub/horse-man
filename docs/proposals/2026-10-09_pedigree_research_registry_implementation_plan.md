## 1. 目的と基本動作

これまで調査した血統情報をレース・チャット・検証サイクルを越えて参照できるリストへ蓄積する。調査依頼時は必ず先に保存済み情報を検索し、必要な情報が確認済みなら再利用し、不足する項目だけを調査・検証・保存する。

処理順は「対象馬の同定 → 必要項目の定義 → 保存情報の照合 → 不足項目の調査 → 検証 → 保存と読戻し → 参照結果の返却」とする。保存済みというだけで正しい・予想に有効とはみなさない。

初期版はGit管理のJSONを正本とする。チャット調査から利用できる小さな検索・検証・保存用スクリプトを先に作り、JRA-VANアプリ完成を待たず再利用できるようにする。DB導入時は同じ識別子・revision・出所を移行し、競合する二つの書込正本を作らない。

## 2. 保存対象を分ける

| 区分 | 保存内容 | 再利用条件 |
|---|---|---|
| 血統の客観事実 | 父・母・母父・祖先と親子関係、確認できた世代 | 同一馬・同一項目が検証済みで出所を追跡できる |
| 系統・内包の派生情報 | 父系・母父系、指定祖先の内包、クロスと位置 | 元の血統と分類定義・計算版が一致する |
| 祖先馬の属性 | 生産国、調教国等 | 属性ごとに根拠を確認する。生産国を調教国の代用にしない |
| 条件別成績・傾向 | 種牡馬・母父・系統別の集計、個人メモ | 対象期間・条件・母数・集計時点が照合できる |

「Danzigを内包する」という事実と「このレースでDanzig内包馬が好成績」という集計は別レコードとする。一般的な適性解釈やユーザーの仮説も事実へ混ぜず、原文と検証状態を保持する。

初期実装の中心は血統事実と再計算可能な派生情報。集計は既存のcondition_stat_snapshot設計に接続し、この機能で独自の評価点・自動加点を追加しない。

### 2.1 欧州型・米国型の定義（利用者指定）

本計画の血統整理・集計・表示における「欧州型」「米国型」は、分類対象の馬自身（父・母父・祖先等）がその地域で調教されていた馬であることを指す。

- 欧州型: 欧州で調教されていた馬。
- 米国型: 米国で調教されていた馬。
- 生産国、出生地、血統登録国、種牡馬の供用地、父系の名称、芝・ダート適性から調教地域を推定して分類しない。例えば米国産でも欧州で調教されていた馬は、生産国を理由に米国型としない。
- 分類対象のhorse_key、確認した調教国・地域、対象期間、出所、観測時刻、使用revision/hashを保持する。欧州の対象国と国→地域の対応は版付き定義として明示し、未定義の国は自動分類しない。米国型を北米全体の意味へ暗黙拡張しない。
- 調教国の決定は§11.8の優先順位による。検索で1国のみ一致した場合はその国を採用して後続調査を停止し、複数国が一致した場合は各国の実際の調教所属時期のうち最も直近の国を選ぶ。従来の最多出走国は新規分類へ適用しない。日付不明・同率最終日・矛盾は保留する。同一出走を比較母数へ二重計上しない。
- 調教地域が未確認・競合の場合はUNKNOWN/CONFLICTとして追加調査へ回し、生産国で補完しない。
- 調教国が不明な場合は、対象馬の名前と識別情報、父/母父/祖先のどれを確認しているか、不明な調教国・対象期間、分類を保留していることをユーザーへ明示し、調教国の情報を求める。分かれば対象期間、調教師・所属、参照資料やURLも提供してもらう。内部検証IDではなく平易な日本語で案内する。
- ユーザー回答を受領したら、回答原文・SHA-256・受領時刻・対象馬/期間・出所種別USER_PROVIDED・確認者を残し、対象馬を同定したうえで専用属性へ保存する。ユーザー提供国として採用できるが、独立した外部原票で確認済みと偽らない。検索で国が既に一致している場合は回答で上書きしない。保存後にrevisionと読戻しを検証し、影響する分類・集計を更新する。
- 回答待ち、回答なし、ユーザーも不明、所属時点不明または情報競合の場合は未確認/競合を維持する。調教国を推測せず、他の作業を先に終えてから未解決馬をまとめてチャット提示する。該当馬の地域分類や対象集計を確認完了と宣言しない。
- 祖先が欧州型・米国型であることと、子孫の馬自身の調教地域は別情報。「欧州型祖先の内包」は対象祖先・世代・経路を明示し、子孫自身が欧州調教馬であると読み替えない。
- 旧記述の「欧州型」「米国型」は、この定義と元出所を照合できるまで未確認候補として保持する。既存の父系分類と同じ項目へ上書きしない。

## 3. 保存構造・馬の同定

新設候補:

- data/pedigree/README.md: 保存契約・検索方法・更新手順
- data/pedigree/horses/<horse_key>.json: 馬と祖先情報の追記型revision
- data/pedigree/aliases.json: 日本語・英語・旧表記等と馬識別子の対応
- data/pedigree/taxonomies/<version>.json: 系統分類の根拠・祖先定義
- data/pedigree/research/<request_id>.json: 必要項目、不足項目、調査結果、保存確認
- scripts/pedigree_registry.py: 検索・不足判定・検証・保存・読戻し
- scripts/test_pedigree_registry.py: 受入条件の回帰テスト

索引は正本レコードから再生成可能にし、索引だけの一致で再利用可否を決めない。名前ではなく血統登録番号・providerの馬IDを優先する。外国馬等で共通IDが無い場合は、provider ID、生年、国、親情報を照合してローカルIDを発行し、同定根拠を保存する。

表記ゆれは候補検索に使う。同名異馬・生年不明・対応不明を自動統合せず、IDENTITY_UNRESOLVEDとして調査対象に残す。祖先馬は独立した馬識別子を持たせ、親子関係から複数の子孫で再利用する。

JSONは明示的なschema_versionを持ち、少なくとも次を保存する。

| 対象 | 最低項目 |
|---|---|
| 馬 | horse_key、外部ID、名称・別名、生年、同定状態 |
| 事実revision | revision_id、対象項目・値、検証状態、前revision、訂正理由 |
| 出所 | URLまたはprovider record key、source_class、origin_group、取得方法、元record hash |
| 時刻 | first_observed_at、captured_at、保存確認時刻、provider timestamp（存在時のみ） |
| 祖先 | generation、父母を辿るpath、ancestor_key、確認範囲 |
| 派生情報 | derived_fromのrevision/hash、分類版、計算版、判定範囲 |
| 調査要求 | 対象、必要項目・世代・祖先・属性、data_cutoff、参照revision、残存不足、次回試行時刻 |

祖先位置は父/母の経路で一意に記録する。5代を既定範囲とするが、依頼が深い世代を要求した場合はその範囲で不足判定する。深さを無限に自動拡張しない。

## 4. 参照・不足判定と追加調査

1. 必要項目を先に定義する。例: 父、母父、5代以内のRoberto/Danzig/Caro内包、母父の調教国。
2. 馬ID、必要範囲、data_cutoff、分類版で検索する。
3. 項目ごとにVERIFIED、PARTIAL、UNVERIFIED、CONFLICT、NOT_FOUND、SOURCE_ERRORを判定する。
4. 確認済み・時点適合の項目を返し、不足・競合項目だけを調査要求へ載せる。
5. 利用可能ならJRA-VAN/JRA一次データ、次にJBIS等の血統DBを参照する。Web補助経路は出所契約に従い明記する。
6. 取得候補をschema・馬の同一性・親子関係・source/provenance・時点で検証する。
7. 新revisionを保存し、同じファイルを読戻してID・内容hash・必要項目の充足を照合する。
8. 調査依頼へ再利用分、追加分、未確認分、保存状態を返す。

再利用の例: 父と母父が確認済みでも5代祖先が未確認なら、父・母父を再取得せず不足祖先を調査する。同じ祖先の属性を複数馬で使う場合も、登録済み祖先レコードを参照する。

内包判定はPRESENT / ABSENT_WITHIN_SCOPE / UNKNOWNの三値とする。指定範囲を完全に確認していない場合、見つからなかったことを「内包なし」としない。クロスの世代・経路と分類の根拠も保存する。

血統事実は一律の日数で失効させない。公式訂正、出所競合、未確認項目、要求世代の拡張があれば再調査する。分類変更時は元血統から派生情報だけを再計算する。条件別統計は期間・条件・cutoffが異なれば再集計する。

## 5. 調査・保存の失敗と競合

NOT_FOUNDは調査先と調査範囲内で未取得だった状態であり、恒久的な不存在を意味しない。通信・認証・parser障害はSOURCE_ERRORに分ける。調査失敗も保存し、同一要求を短時間に繰り返さない。

初期値として一時障害は最大2回再試行、NOT_FOUNDは24時間後に再試行可能とし、設定で変更可能にする。利用者の明示再調査、別sourceの利用、公式更新で再試行可能にする。有限の時間予算を要求単位で指定し、締切時は残存不足を返す。

情報競合は元値・候補値・出所を両方残してCONFLICTとする。多数決で上書きしない。優先sourceと馬ID・revision確認で解決できた場合のみ、訂正理由を持つ新revisionを追加する。

同じ要求・source record・hashの再実行で重複revisionを増やさない。ローカルは単一Writerと原子的置換、Gitは読取時のbranch HEAD/blob SHA照合で競合を検出する。別作業の更新後は最新版を読み直して項目単位で再統合し、内容を失う強制pushをしない。

Git保存は作業ブランチへコミットし読戻す。再利用時はmainに限定せず、明示された調査作業ブランチも参照可能とし、commit SHAを記録する。新規単独調査はresearch/pedigree/<request_id>、予想中の調査は既存prediction/YYYY-MM-DD契約に従う。正式共有はmain向けPR経由とする。

保存に失敗した情報は未保存と明示し、要求を再開可能にする。取得済みの有効情報は現行manualで許される範囲で利用できるが、調査リストへの保存完了や予想snapshotの保存完了を代わりに宣言しない。予想snapshotの既存intent/receipt監査は独立して維持する。

## 6. 過去の調査情報の移行

リポジトリの重賞ノート、validation records、snapshotsを検索し、血統に関する既存記述を候補へ抽出する。参照可能な過去チャット等は出所を識別できる場合のみ対象に追加する。全履歴を取得できたと推測しない。

移行manifestに対象ファイル・commit・抽出数・検証済み数・未確認数・重複・競合・未アクセス範囲を記録する。旧ファイルは削除せず参照リンクを残す。父母の客観事実、系統判定、傾向の主張を分解して取り込む。

元sourceが追跡できない旧記述はUNVERIFIEDで保存し、利用要求時に不足項目として照合する。「以前調査した」というだけでVERIFIEDにしない。移行日に判明した事実を過去の予想時点で既知だった証拠へ遡及変換しない。

## 7. 予想・時点・Production境界

再利用するrevisionはfirst_observed_at <= data_cutoffを満たすものとする。後日の訂正を過去予想へ適用せず、実際に使用したrevision・hash・分類版を予想根拠へ固定する。再参照時刻を元情報のfirst_observed_atへ置き換えない。

原文の公開日時だけで自システムの観測時刻を捏造しない。過去公開資料から新規作成する遡及研究はREPLAYとして扱い、発走前に保存・観測したFORWARD証跡と分離する。

血統の保存・検索・再利用はデータ基盤であり、現行manualで許可された血統情報の利用を新featureと同一視しない。一方、新しい血統スコア・重み・適性統計はShadow検証後、別PRで昇格する。

重賞固有の血統好走傾向は次期契約どおりProduction固定後のShadow比較に限定する。通常Production向けの参照要求からこの集計を返さない。馬個体の直接血統とレース固有集団傾向を返却APIでも分ける。

AIの調査結果は候補入力とし、未確認の祖先・分類を生成して保存しない。保存処理はスクリプトまたはCore Serviceの検証済みWriterが担い、AIへDuckDB直接書込権限を与えない。

## 9. 検証・受入条件

PR69では次を要件と実装・テスト結果の対応表で確認する。Phase 2以降に依存する項目は、依存先の完了時点と未実施範囲を明示して引き継ぐ。

1. 登録済み・検証済み・同一要求を再実行すると外部調査0件で返せる。
2. 父は登録済み、母父だけ不足の場合、母父だけが調査要求へ載る。
3. 複数馬で共通祖先を参照しても同じ事実を重複取得・加点しない。
4. 同名異馬・曖昧な別名を誤統合しない。
5. 不完全な血統から「指定祖先なし」を返さない。
6. 分類版変更時は元血統の再取得なしに派生情報を再計算できる。
7. source不一致はCONFLICTで保持し、訂正前revisionで過去予想を再現できる。
8. cutoff後の新規情報・訂正・統計更新を過去FORWARD予想へ混入させない。
9. 同一保存要求の再実行・中断後再開で重複が増えず、競合更新を失わない。
10. 追加調査→検証→保存→読戻し→次回検索の一連の実行が通る。
11. NOT_FOUND・SOURCE_ERROR・保存失敗を区別し、無限再試行せず不足を返す。
12. 旧記述の出所不明データを確認済みへ自動昇格しない。
13. 重賞固有集計と新スコアがProduction入力へ侵入しない。
14. 血統リスト保存成功だけで予想snapshot/receipt保存完了と誤認しない。
15. JSON→DB移行後もID・revision・hash・時点・出所が一致する。
16. v1.6.1の既存監査、次期v2監査、固定済み予想が変更されない。
17. 欧州型・米国型を対象馬自身の確認済み調教地域から判定する。生産国と調教地域が異なる例、地域未確認、複数地域の履歴、祖先と子孫の区別、分類母数の二重計上防止を検証する。

初期基盤の効果は再利用件数、不足調査件数、外部照会数、取得時間、coverage、競合件数、保存失敗件数で測る。的中率の改善を保存基盤の完成条件にしない。

## 10. ロールバック・未解決事項

問題時は新しい参照経路を停止し、直前の検索実装・検証済みrevisionへ戻す。調査結果とrevision履歴は削除しない。DB移行前にはexportと照合結果を保存し、復帰先のWriterを一つに固定する。過去予想を最新血統で再計算・上書きしない。

正式実装前の確認事項:

- 各sourceで取得可能な血統の世代・ID・訂正通知・調教国属性の実仕様。
- Web自動取得の利用条件・アクセス制限。取得できないsourceは手動候補入力で同じ検証・保存経路を使う。
- 参照できる過去チャット等の範囲。未アクセス範囲はmanifestに残す。
- Phase 2時点の実DB schemaとのDDL整合。

これらはsource adapterや移行範囲に関する確認事項であり、「保存済みを先に照合し不足だけ調査する」という基盤仕様の着手を妨げない。

### 11.2 対象範囲・残件管理

- 既存候補を客観事実、系統/内包、調教地域、適性/好走傾向の主張へ分離し、元資料のcommit・行・hashを維持する。
- 対象資料一覧、参照済み/未アクセス範囲、対象馬ID、必要項目と世代、確認済み/未確認/競合/取得不能/対象外の件数と理由をmanifestへ保持する。

対象期間、地域/主催者、レース条件、血統条件、要求世代、分類版、結果の採用状態、情報cutoff、計算版を実行前の版付き定義として固定する。初期入力は既存Phase 2の取得契約で確認できる範囲とし、海外を含む未取得範囲を網羅済みと扱わない。全条件の直積を一度に生成せず、指定した集計要求を処理する。

| 区分 | 項目 |
|---|---|
| 血統軸 | 父ID、母父ID、父系/母父系、指定祖先内包、定義済みクロス |
| 調教地域軸 | 分類対象の父/母父/祖先IDと調教履歴。欧州型・米国型は2.1の定義を使用 |
| レース条件 | 競馬場、芝/ダート、距離または版付き距離帯、クラス、新馬、馬場状態。追加条件も事前宣言 |
| 入力 | 対象条件の全出走馬、馬ID、race ID、公式着順・結果状態・取消/除外/中止、血統revision、出所 |
| 出力 | 出走数、実頭数、対象レース数、勝数、連対数、3着以内数、各率、欠測・競合・保留・除外数と理由 |

### 11.4 母数・欠測・重複・結果の扱い

- 計上単位はrace ID × horse IDの一出走。入力行の重複は除去し、同じ馬の異なるレースへの出走は別出走として数える。実頭数はhorse IDで重複除外する。
- 血統条件ごとに対象全出走数、判定済み数、条件該当数、未確認数、競合数を示す。該当群の率の分母は公式結果が確定した有効出走数とし、率の分子も同じ対象集合から数える。
- 取消/除外等の非出走は成績母数から除外し件数を残す。競走中止/失格等の実出走、同着、結果訂正はproviderの公式仕様を確認して版付き結果規則を定義し、恣意的に不利な結果を除外しない。未確定結果は保留。分母0の率はnullとする。
- 祖先の複数経路・クロス回数で一出走を重複計上しない。同じ馬が複数血統条件に該当し得るため、重なりを表示し、各群の件数を合算して全体件数としない。
- 不完全な祖先範囲はUNKNOWNとし、「内包なし」群へ混ぜない。未確認・競合を0や平均値で補完しない。結果coverageと血統coverageは別々に報告する。
- 比較対象は同じ期間・レース条件の全体または非該当群として事前定義し、欠測条件と対象集合も表示する。小標本、同一馬の反復出走、条件探索による見かけの差を明記し、生の率だけから強い適性を断定しない。

### 11.5 時点・保存・再利用

既存condition_stat_snapshotを拡張して利用し、血統専用の重複した書込正本は作らない。具体schema/DDLと実装ファイル名は各Phaseの既存コード確認後に確定する。

保存内容は集計定義ID/hash、対象入力manifest/hash、出所、使用血統・同定・調教履歴revision/hash、分類版/hash、計算版、期間、cutoff、生成時刻、対象出走集合または再現可能な参照、件数/率/coverage、残存不足、使用modeとする。原子保存・読戻し・hash照合を行い、保存失敗を成功扱いしない。

同じ入力・定義・版で再実行した場合は同じ結果を返す。新規公式結果、訂正、血統確認、分類変更の影響範囲だけを再計算可能にし、旧snapshotは上書きしない。出力の再計算を入力の外部再取得と混同しない。

後日同定・確認した血統による過去成績分析はREPLAY研究として明示する。FORWARDで使用する場合は、結果・同定・血統・調教地域・分類の各情報がcutoffまでに観測/確認可能であったrevisionだけを参照する。分析対象レース自身の結果やcutoff後の訂正を入力へ混入させない。

重賞固有集計はProduction固定後のShadow参照に限定する。新統計の自動加点・重み調整・正式採用はPhase 8の検証、人間承認、別PRを必要とする。オッズ、人気、回収率、実購入記録を本集計の必須入力にしない。
