## 1. 目的と検討の背景

戦歴から現在の基礎能力を評価し、今回の適性・展開・状態によって評価を調整する。その際に、血統・個体の実走・集計データの役割と優先順位を明示すると、予想精度や判断の再現性が改善するかを検証する。

ユーザー案は「能力を土台とし、条件評価では血統、戦歴、各種データの順に重視する」。対案は「能力を土台とし、適性判断では関連性の高い個体実走を優先し、血統で未知の適性を推定し、集計で補助する」。

どちらが優れるかは未検証。既存ルールにも基礎能力と今回発揮能力の分離があるため、単なる言い換えを改善として数えず、何が追加で変わったかを測る。

## 4. 比較する案

| 系統 | 内容 | 比較で確かめること |
|---|---|---|
| P：現行基準予想 | 現行ルールで作成・固定したProductionをそのまま使用 | 全比較の対照。新案のために再生成しない |
| A：個体実走優先案 | 能力を土台に、適性は関連する個体実走→血統推定→集計補助の順に判断 | Pに対して、優先順位と根拠の整理が追加価値を持つか |
| B：血統優先案 | Aと同じ能力の土台・入力・評価項目を使用し、適性推定の優先を血統→個体実走→集計補助へ変更 | Aとの差から、血統優先の効果と悪化条件を確かめる |

AとBはどちらも比較専用。Bはユーザー案を検証可能にするための具体化案であり、開始前に採用する判断手順を固定する。

A／Bの共通事項：

1. 今回の要求能力を先に整理する。
2. 相手レベル、着差、ペース、ラップ、追走・末脚、近走推移から共通の能力の土台を作る。
3. 適性・展開・状態を調整する。Bでも血統で能力の土台や重大な状態事実を上書きしない。
4. 集計データは今回との接続を説明できる場合だけ補助に使う。
5. 新しい一律配点・固定重みは導入しない。文章による判断と順位・確率の変化を対応付ける。

A／Bの相違が生じる場合：

- 血統と個体実走が一致：同じ方向で評価し、二重加点しない。
- 両者が衝突し、双方に開始前に定義した有効な根拠がある：Aは個体実走、Bは血統を優先する。採らなかった根拠も記録する。
- 片方が未取得・関連性不足：無理に優先せず、利用可能な根拠で評価する。
- 個体実績がない：Aも血統を使える。未経験だけを不適性としない。
- 血統を先に見るだけで実走を優先して結論を出した場合：Bの優先順位変更とは数えず、分析順序だけの変更として記録する。

## 5. 評価項目の計画表

| 段階 | 評価すること | 主な根拠 | 記録・重複防止 |
|---|---|---|---|
| 要求能力 | 今回どの能力が必要か | コース、距離、馬場、想定展開 | 想定シナリオを共通化する |
| 能力の土台 | 現在の相手関係で通用するか | 対戦相手、グレード、着差、ラップ、内容、推移 | 着順・グレード名だけで順位を決めない |
| 条件適性 | 今回の能力発揮に向くか | 個体実走、血統、コース・距離・馬場 | A／Bの主な比較対象 |
| 展開・枠 | 望む位置を取れて、能力を出せるか | 発馬、脚質、同型、馬群対応、枠 | 血統の一般論で枠の有利不利を決めない |
| 状態・ローテ | 現在の能力を出せる状態か | 個体の間隔別内容、調整過程、当日馬体重 | 血統だけでローテや仕上がりを断定しない |
| 集計補助 | 個体評価を補強・反証するか | 騎手、厩舎、枠、前走条件、ローテ等 | 期間・母数・条件・個体との接続を記録 |
| 不確実性 | 判断できない部分は何か | 初条件、取得不足、根拠の衝突 | 中心評価の減点と推定幅の拡大を分ける |

「前走上がり8位」という個体の走りは能力・展開評価へ接続し、「前走上がり6〜10位が当該重賞で好成績」という集計傾向は補助材料として分ける。

同じ距離適性を示す個体実績・父系傾向・産駒集計は一つの評価項目へまとめる。根拠が複数あることによる確信の変化と、能力・適性の加点を混同しない。

## 7. 前向き比較の条件

- 同じレース、出走対象、情報締切、共通入力をA／Bに使う。
- Pの入力が不足している場合は、A／Bのための追加取得とその影響を記録する。追加情報がある例を「優先順位だけの効果」と断定しない。
- A／Bに同じ追加情報を与える。片側のみ取得できた例はA対Bの同一入力比較から除き、理由を残す。
- 既存E-09・51B・U-02等の補正後順位をA／Bの土台にしない。観測事実を再利用し、判断を重ねない。
- 結果・当該レースの途中経過・発走後情報は入力しない。血統集計等も情報締切時点の内容を使う。
- 対象レースは結果を見る前に決め、都合のよい成功例だけを抽出しない。
- 適性実績の有無、血統との一致／衝突、クラス・距離・馬場等の分類を発走前に付ける。
- 取消や重大な情報変更があれば、現行更新契約に従うPにA／Bを対応付ける。対応できなければ対比較は不適格とする。
- 比較追加が既存の予想・必須Shadowの締切を圧迫する場合は、追加案を打ち切り「未実施／時間不足」を記録する。
- 発走前は時刻付きチャットsnapshotへ固定し、Gitへの保存は結果後の回顧で一括する。

## 9. 評価指標と判定案

本追加検証は予想判断の比較を目的とし、現行サイクルの主KPIを置き換えない。

| 区分 | 指標・確認事項 | 判定上の扱い |
|---|---|---|
| 主要候補 | 同一レースの勝率Brier Score差（A−P、B−P、B−A） | 小さいほど良い。実施前に下記定義を固定する |
| 予想順位 | ◎勝率・◎3着内率・上位3頭の勝ち馬捕捉率 | 精度の非劣化を確認。分子・分母を併記 |
| 変更の効果 | 血統で順位を変えた例、実走との衝突例の改善／悪化 | 変更例だけでなく全対象の結果も示す |
| 確率・確信度 | 確率校正、上位確率集中、A/B/C/D別精度 | 平坦化や過信が増えていないか |
| 条件別 | 個体実績あり／なし、一致／衝突、距離・馬場・クラス | 結果を見て追加した分類は探索分析と明示 |
| 運用 | 記録完了率、取得率、追加時間、打切り率 | 追加コストに見合うか |
| 重複 | 現行と同じ結論・根拠の割合、独自の差分 | 言い換えに留まる場合はルールを増やさない |

Brier Score案：単独勝者があるレースについて、各馬の予測勝率を0〜1で表し、レースごとに「各馬の（予測勝率−実結果）²の合計」を計算する。勝者の実結果は1、他馬は0とし、レース平均で比較する。各案の勝率合計は1を確認する。1着同着・競走不成立はこの指標の対比較から除き、別途件数と理由を記録する。欠測した案の確率を結果後に作らない。

- すべての比較に対象件数・適格件数・欠測件数を併記する。
- 確率が欠けた例は確率KPIだけ不適格とし、発走前順位があれば順位KPIの適格性は別判定する。
- P対A、P対B、A対Bの分母を明記し、三者比較の結論は原則として三者が揃う共通集合で判断する。
- 改善幅・非劣化許容幅・必要件数・終了条件は工程2で事前登録する。未確定のまま正式検証を開始しない。
- 件数不足や条件の偏りがある場合は継続検証／判断保留とし、単発的中で優位を断定しない。
- 手順確認用の過去例と、新規の前向き比較は合算しない。
- ROI・買い目比較は初期段階の採用根拠にせず、必要なら後続計画で同一オッズ時点・同一資金条件を固定する。
