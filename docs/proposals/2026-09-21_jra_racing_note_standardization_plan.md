## 1. 目的と設計方針

各重賞を翌年も同じファイルで利用できるよう、記載構成と更新単位を統一する。当年の確定結果を必ず記載し、既に把握している例年傾向と取得した過去データを照合して、翌年に確認すべき課題へつなげる。

情報を次の4種類に分ける。

| 区分 | 内容 | 更新・保持方針 |
|---|---|---|
| 通年の知識 | コース構造、開催条件変更、ユーザー蓄積傾向、過去データ、根拠付き仮説 | 有用な限り保持。条件・根拠・現状を更新する |
| 当年結果 | 開催条件、確定着順、照合に必要なレース事実 | 必須。最新の結果年度を明示して更新する |
| 当年照合 | その年の結果と事前に把握していた傾向の一致・不一致 | 対象年度1年分だけ保持。翌年の照合時に置換する |
| 翌年課題 | 不明点、反例、必要な追加調査、次回確認事項 | 未解決事項を引き継ぎ、解決済み・不要な項目を整理する |

「積み重ねない」の対象は年度ごとの照合文・回顧文であり、傾向を支える過去の事実データではない。過去結果の表と、過年度の照合文章を区別する。

1重賞1固定ファイルを維持し、年度別ファイル、`archive/`、`old/` は作らない。年をまたぐ状態はGit履歴で確認する。予想・購入の正式ルールは `docs/manual/README.md` を入口とする現行manualに従い、ノートから新しい加点・消し条件を自動適用しない。

## 2. 現状と解消する問題

現行15重賞の内容・見出しと、`AGENTS.md`、`docs/manual/README.md`、yosouの共通・JRA README、validationの保存方針を確認した。下表は文書構造の調査であり、記載済みの競走結果や統計を外部情報で再検証したという意味ではない。外部の結果・過去傾向取得は実装工程に含める。

| 分類 | 対象ファイル | 主な整備内容 |
|---|---|---|
| 年次ノート型 | `allComers.md`、`kobeShimbunHai.md` | 結果・出典・集計期間の固定欄を追加し、散在する観察内容を整理。神戸新聞杯は複数年データの補完が必要 |
| 詳細回顧・過去傾向混在型 | `centaurStakes.md`、`challengeCup.md`、`chukyo2saiStakes.md`、`chukyoKinen.md`、`keenelandCup.md`、`keiseiHaiAutumnHandicap.md`、`niigata2saiStakes.md`、`niigataKinen.md`、`sapporo2saiStakes.md`、`sapporoKinen.md`、`shionStakes.md` | 既存の傾向・データを保全し、買い目・収支・検証詳細の保存境界を整理する |
| 当年回顧中心型 | `roseStakes.md`、`stLiteKinen.md` | 当年結果を保持し、過去傾向・照合・翌年課題を補完する |

主な問題は以下のとおり。

- 章順・見出し・粒度が異なり、必要な情報の位置が重賞ごとに変わる。
- ユーザーの経験的な傾向、取得済みの統計、当年結果から生まれた仮説が同じ説明に混ざる。
- 当年を含む「直近5年」と、当年結果との比較に使う事前の集計を混同しやすい。
- 既存READMEでは保存対象外とされる買い目・収支・KPI・正式回顧が旧ファイルに残る。
- 傾向が使えなくなったことの判定や、出典が確認できない場合の扱いが統一されていない。
- validationはサイクル終了時に削除されるため、`main` の相対リンクだけでは翌年に根拠を追えなくなる。

### 既存運用文書の不整合

`docs/yosou/jra_racing/README.md` の「予想中は記録目的のGit書き込みを行わず、チャットをsnapshotとする」という記載、および `docs/yosou/README.md` の末尾のフローは、現行manualの「分析途中は書き込まず、正式固定した最小snapshotは発走前に永続化する」という契約と整合していない。

後続実装では両READMEの該当記述をmanualへの参照に整理する。重賞ノート側でsnapshotの保存方式を再定義しない。予想中に年次ノートを更新する必要はなく、今回の構成統一で発走前処理を増やさない。

## 3. 共通構成と配置

新規に `docs/yosou/jra_racing/_template.md` を用意する。重賞ファイルのH1はレース名、H2は以下の名前と順序に統一する。READMEとテンプレートはレース件数から除外する。

| 章 | 内容 | 更新単位 |
|---|---|---|
| 1. 管理情報 | レース識別、対象年、結果年度、照合年度、次回利用年、状態、更新日 | 状態変更時 |
| 2. レース構造・適用条件 | コース、距離、時期、斤量条件、変更履歴と比較可能性 | 変更時 |
| 3. 通年の傾向・仮説 | ユーザー蓄積傾向とデータ由来の傾向を識別して管理 | 根拠更新時 |
| 4. 過去データ・集計条件 | 保持する事実、期間、母集団、欠測、集計定義 | 新データ取得時 |
| 5. 当年の確定結果 | 必須の結果表、開催条件、レース内容、確認状況 | 結果確定後 |
| 6. 当年結果との照合 | 事前傾向×当年事実×判断。単年度のみ | 毎年置換 |
| 7. 翌年へ向けた課題 | 問い、確認方法、必要データ、完了条件 | 毎年整理 |
| 8. 次回利用チェックリスト | 利用前に確認するレース固有項目 | 毎年整理 |
| 9. 出典・参照先 | 情報源、取得時点、対象期間、確定履歴へのリンク | 参照更新時 |

固定のH2を維持し、レース固有の説明はH3以下に置く。項目が未取得・対象外でも章は消さず、理由を書く。予想がない年も結果・過去傾向の照合は作成できる。

### 3.1 管理情報

- `対象年`：今回整備・調査する開催年。
- `結果年度`：第5章に実際に記載している結果の年。
- `照合年度`：第6章が評価している年。
- `次回利用年`：原則として対象年の翌年。開催未確定ならその旨も併記。
- `状態`：準備中／結果未確定／結果確認中／照合未完了／更新完了／開催中止。
- 更新日、レース識別子、当年の開催日・競馬場・Rを記載する。

通常の更新完了時は「対象年＝結果年度＝照合年度」。暦が変わっただけで結果年度を進めない。例えば2027年の開催前には、2026年の結果・照合を「前回実績（2026年）」と明示して参照できる状態を維持する。

## 4. 通年の傾向とデータの扱い

### 4.1 傾向台帳

各重賞内で再利用しない固定ID `T-001` 等を割り当て、既存のユーザーメモを漏れなく対応付ける。

| 必須項目 | 記載内容 |
|---|---|
| ID・観点 | 血統、枠、脚質、前走、開催条件等 |
| 傾向・仮説 | 曖昧な表現を避けた確認可能な命題 |
| 由来 | ユーザー蓄積／公式集計／独自集計／単年観察 |
| 適用条件 | 場、距離、馬場、開催時期、斤量条件等 |
| 根拠 | データID、対象期間、標本数、出典ID |
| 状態 | 継続観察／弱化／新規候補／保留 |
| 利用上の注意 | 交絡、少数例、例外、未確認範囲 |
| 最終確認日 | いつ、どの範囲を再確認したか |

ユーザー蓄積傾向は、裏付けが未取得でも由来を維持して「保留・独立検証待ち」として保持する。出典未確認を、誤りや無効と同一視しない。結果後に生まれた仮説には発見年を付け、その年の事前仮説として扱わない。

「弱化」は削除や正式ルールの降格を意味しない。継続・弱化等はこのレースの知識管理上の状態であり、Productionへの適用可否はmanualを正とする。

### 4.2 過去データの取得・集計

1. 既存ファイル内のデータと出典を棚卸しし、有効なものは再利用する。
2. 不足する結果・開催条件はJRA公式を優先して取得し、取得不能部分は確認できる代替ソースと理由を明記する。血統はJBIS等で確認する。
3. まず直近5開催分を基本の比較対象とし、既存の10年集計・条件別データも保持する。開催中止年は標本0件であり、5暦年と5開催を混同しない。
4. 競馬場・距離・開催時期・斤量条件の変更を識別し、異なる条件を単純合算しない。近年全体の参考集計と現行条件に適合する集計は区別する。
5. 集計には期間、対象レース、除外条件、母数、分子、定義、当年を含むか、取得日・出典を付ける。欠測を0として扱わない。

基本観点は血統、年齢・性別、枠・馬番、脚質・位置取り、前走レース・格・距離・着順・上がり順位、ローテ、馬場、騎手・厩舎、人気とする。全観点の統計が揃わない場合は取得範囲と次回課題を残し、取得したふりをしない。

上位3頭だけのデータから「該当馬の複勝率」を算出しない。複勝率には該当する全出走馬の頭数が必要であり、上位内の構成比とは別物として表示する。前走上がり順位などは指標の定義・同順位の扱いも明記する。

ローリング集計の表示範囲を更新しても、範囲外となったデータを自動削除しない。条件比較や再集計に使える元データは簡潔な表で保持する。同じ事実の重複行や、再計算できる旧集計表の重複は整理できる。

### 4.3 継続保持と削除基準

| 状況 | 扱い |
|---|---|
| 単年で不一致・標本が少ない | 弱化または保留。自動削除しない |
| 出典切れ・再取得できない | 確認済み範囲と欠測を記載し、再確認課題にする |
| 開催条件が変更された | 現行条件への適用を停止。代替開催・比較研究の用途があれば保持 |
| 重複情報 | 根拠を統合し、一方に集約する |
| 誤記・誤集計が確認された | 正しい内容へ訂正。元情報と訂正理由は変更差分で追跡する |
| 現行条件にも比較・再検証にも用途がなく、今後の使用見込みもない | 理由をPRに記載して削除する |

年齢の古さ、直近5年から外れたこと、一度外れたことだけを削除理由にしない。削除時は、対象ID、根拠、利用見込みがない理由、関連する課題・リンクへの影響をPRへ記載し、セルフレビューする。本文に廃止履歴を積み上げず、Git履歴で保持する。自動の期限切れ削除は設けない。

## 5. 当年結果を必須とする仕様

結果確定済みのレースは、最低限次を本文に残す。リンクだけで代用しない。

- 結果年度、開催日、競馬場、R、距離・コース、天候・馬場、出走頭数。
- 確定1～3着の着順・馬番・馬名。出走数不足等で3着が成立しない場合は理由。
- 勝ち時計、および傾向照合に必要な人気、枠、通過順、上がり等。値が取れない場合は未取得と記載。
- 結果の出典、確認日、取消・除外・失格等の照合に影響する事項。

全頭結果が必要な仮説は対象馬を追加して確認する。例として「馬番10番以降が不利」の確認を上位3頭だけで完了扱いにしない。

未開催・開催中止・結果未確定・取得障害を区別し、結果を創作しない。開催済みなのに必須の確定結果が取得できない場合は「結果確認中」とし、初回移行の完了件数へ算入しない。開催中止は公式確認と理由を記載すれば状態整理として完了できるが、結果照合済みとは扱わない。

## 6. 当年照合と翌年課題

### 6.1 照合を毎年置換する

第6章は単年度の表だけを置き、過年度の照合表を下に追記しない。表は次の列を持つ。

`傾向ID｜当年を除く比較根拠・期間｜当年の観測事実｜一致／一部一致／不一致／判定不能｜解釈・留保｜翌年の確認事項`

基準となる集計と、当年を追加した更新集計を区別する。2026年の照合では原則2025年以前の根拠を使い、2026年の結果を含む集計で2026年を検証したように書かない。既存の2022～2026年集計から当年前の集計を復元できない場合は「事前比較根拠未復元」とし、判定を保留する。結果後に取得した過去データによる照合は「事後取得データによる照合」と明記し、当時の予想根拠だったと表現しない。

照合後、残す価値のある知見だけを第3章の状態・条件・根拠へ反映する。当年限りの説明文を毎年複製しない。単年の一致・不一致だけで一般則や固定加点へ変換しない。

当年予想の要約を置く場合は、発走前記録が確認できる範囲に限定する。ない場合は「予想との比較は実施せず、結果と傾向のみ照合」とする。正式回顧やShadow成績をこの章へ移さない。

### 6.2 翌年課題を実行可能な形にする

`課題ID｜関連傾向ID｜確認したい問い｜必要データ・確認方法｜実施時点｜完了条件｜状態`

例：「道悪でも内枠優勢か」を、馬場別の全出走馬・枠・着順を取得し、同じ開催条件で比較する課題として記載する。「来年気をつける」だけで終わらせない。標本不足なら結論を出すことではなく、取得可能な範囲と不足理由を確定することを調査の完了条件とする。

未解決課題は同じIDで引き継ぐ。解決した知見は第3・4章へ反映し、完了済み課題の年表を増やさない。汎用的な購入監査・KPI改善はvalidation側へ渡し、レース固有課題と分ける。

## 8. 年次更新の手順

### 結果確定後

1. manualに従って正式回顧をvalidationへ保存する。事前記録がない場合はyosou共通READMEの例外に従い、確定事実による傾向更新のみ行う。
2. 現行ノートと出典を確認し、当年を含まない比較根拠を特定する。
3. 当年結果を取得・照合し、第5章を更新する。
4. 第6章をその年度の照合へ置換する。
5. 第3・4章を更新し、継続利用できる知識・根拠を保持する。
6. 第7・8章の未解決課題と次回確認事項を整理する。
7. 確定commitへの参照、年度、欠測、保持・削除理由を点検して保存する。

### 2026年から2027年への更新例

| 時点 | 結果・照合 | 通年データ | 課題 |
|---|---|---|---|
| 2026年整備完了 | 2026年結果・照合 | 2025年以前の比較根拠と2026年反映後データを区別 | 2027年用 |
| 2027年開催前 | 2026年を前回実績として保持。2027年結果は未確定と明示 | 2026年までのデータを今回条件と照合 | 未解決項目を確認 |
| 2027年結果確定後 | 2027年結果・照合へ置換。2026年の照合文は本文から除く | 2027年を追加・再集計。2026年の事実も有用なら保持 | 2028年用へ整理 |

更新を途中で止めた場合は「結果確認中」「照合未完了」等を明示し、古い照合を当年の完了結果として表示しない。

## 9. 実装工程と変更対象

| 工程 | 作業 | 成果物・完了条件 |
|---|---|---|
| 1. 棚卸し | 実装時の最新mainを読み、15ファイルと追加分を確認。旧各節を保持／移管／履歴参照／補完に分類 | PR本文の移行対応表。元節と移行先、未取得項目が追跡可能 |
| 2. 仕様・雛形 | JRA READMEに章構成・年度・保持削除基準を定義し、テンプレートを追加 | `_template.md`、JRA README。共通READMEの不整合箇所をmanual参照へ修正 |
| 3. 代表移行 | `allComers.md`、`centaurStakes.md`、`roseStakes.md` を先行移行 | 年次型・混在型・不足型の3種類で情報欠落がないことを確認 |
| 4. 全件移行 | 残り12件と実装時の追加ファイルを同構成へ移行。必要な過去情報を取得 | 当年結果、既存仮説の対応、取得状況、翌年課題が揃う |
| 5. 年次更新確認 | 2026→2027の模擬更新を差分で確認 | 当年照合が増殖せず、通年根拠が意図せず消えない |
| 6. セルフレビュー | 受入条件と保持・削除の本質的な差分を確認 | レビュー結果と残課題をPRへ記載 |

代表移行と全件移行はレビュー可能な単位でPRを分けてもよい。初回移行の完了は全件の確認後とし、一部の成功を全体完了とは扱わない。

変更予定は、JRA README、テンプレート、15重賞ファイル、必要箇所のみの `docs/yosou/README.md`。現行サイクルの正式回顧に欠落がある場合だけ、既存のvalidationレコードを照合して補完する。manualの判断基準や将来のコード実装は変更しない。今回は文書運用の整備であり、独自の自動取得システムやCIを追加することは必須にしない。

### 9.1 旧形式の回顧・収支を消す前の確認

- 既存のvalidation記録と照合し、現行サイクルで必要な情報が未保存なら、元の記録と適格性を保って先に移管する。重複集計やKPIへの新規算入は行わない。
- サイクル外の過去回顧は現行サイクルへ投入しない。削除前の確定commitの旧ファイルを参照先として確保する。
- 予想記録の欠落や不適格性を移行で「解消済み」にしない。発走前snapshotの後付け再構成は行わない。
- 保存済みの根拠と到達可能な履歴を確認してから、yosou側の詳細を整理する。
- 当年結果、ユーザーメモ、過去の事実データを正式回顧と一括削除しない。

### 9.2 翌年も利用できる参照

validationへの参照は、存在を確認した確定commitの `blob/<commit>/<path>` を保存する。サイクル終了後に現行ツリーから削除されても追跡できるようにする。URL中のcommitは推測しない。

外部のデータ分析ページは翌年に内容が更新される可能性があるため、URLだけでなく、確認した対象期間・数値・母集団・確認日を本文へ残す。翌年に同じURLを開いたときは、旧集計と同じ内容だと決めつけない。

## 10. 受入条件・確認方法

- [ ] 全重賞ファイルが9章の共通構成を持ち、レース固有の情報を維持している。
- [ ] 開催済みの2026年対象レースは、本文の確定1～3着と開催条件、出典が揃っている。未取得は完了扱いになっていない。
- [ ] 既存のユーザー蓄積傾向が台帳に対応付けられ、無根拠に削除・公式傾向化されていない。
- [ ] 過去データの期間・母集団・条件変更・欠測・当年の含有が識別できる。
- [ ] 複勝率等の分母が正しく、上位内構成比と混同していない。
- [ ] 当年照合に当年込みの集計を事前根拠として使っていない。
- [ ] 根拠不足の項目が判定不能・課題として残り、無理に一致／不一致に分類されていない。
- [ ] 翌年課題に必要データ・実施時点・完了条件がある。
- [ ] 2027年の模擬更新で2026年の照合文が置換され、有用な2026年の事実データは残る。
- [ ] 単年不一致、5年窓からの退出、出典切れだけでデータが削除されていない。
- [ ] 旧正式回顧・収支は移管または確定履歴参照を確認済みで、現行サイクルの集計を変えていない。
- [ ] validationの現行ファイルがなくても、確定履歴から参照できる。
- [ ] READMEのsnapshot契約が現行manualと整合し、定義の二重管理がない。
- [ ] 傾向管理からProduction順位・確率・正式買い目への自動反映が追加されていない。

確認は文書差分・リンク・対象ファイル一覧を中心に行う。数値を変更した場合のみ対応する出典と計算を再確認する。年次更新、条件変更、欠測、単年反例、削除、履歴リンクのケースを代表例で確認し、本質的な問題が残らなければ検証を終了する。

## 11. この計画書のセルフレビュー

- 「結果必須」と「照合は単年度」を別項目として定義し、翌年開催前に前回結果まで消してしまう運用を避けた。
- データ保持とローリング集計を分離し、直近5年から外れた有用なデータを自動削除しない方針にした。
- 旧ファイルの買い目・回顧を機械的に消さず、現行サイクルへの移管と過去履歴参照を区別した。
- 当年結果を含む集計による循環的な照合、単年での一般化、取得不能時の見かけ上の完了を防ぐ条件を追加した。
- 本計画では競走結果の再取得・事実訂正・既存ノートの移行は実施していない。実装時に未取得や矛盾が見つかった場合は、対象項目と影響を同じ作業チャットで報告する。
