## 整理後の責務

1. `docs/manual/README.md`: チャットの入口と読み込み先。予想・買い目・回顧の詳細定義を複製しない。
2. `00_core`: 対象集合、時点、実行順、引継ぎ。`10_prediction` / `20_conditional` / `30_betting` / `40_shadow`: 各判断・比較の唯一の定義。`50_review`: サイクル登録、KPI適格、回顧と集計の完了条件。
3. `docs/validation/README.md`: 現行サイクルの索引と状態。snapshot・receipt・日別recordの書式や読戻しは各運用README、記入欄はテンプレートに置く。サイクルファイルには計画と実測を区別して残す。
4. `docs/proposals/`: 作成当時の調査・計画の履歴。現行ルールをここから再定義しない。第2サイクルの確定前データと監査根拠は、終了審査が済むまで保持する。

## 実施順

### 1. 参照と状態の整備

- 上記Owner表に沿って重複箇所・リンク・版・「適用中/履歴」を一覧化し、現在の入口にある古い状態表示を正す。
- `40_shadow` の旧サイクル優先順位・過去の具体例は、現行の適用条件と区別する。削除前に現行manual・検証記録からの参照を確認する。識別子とGit履歴を切断しない。
- ここでは予想の順位、確率、券種・配分、Shadowの適用条件、保存適格条件は変更しない。

### 2. 予想から回顧への引継ぎを一本化

- 初回の候補台帳、最終の未取得一覧、保存本体と確認証跡、回顧の対象集合を、Ownerとテンプレートの対応表で追えるようにする。同じ内容の二重記入をなくし、参照先を固定する。
- 正常な最終対象外、未依頼、工程未実施、取得不能、保存成否不明を別状態で引き継ぐ。簡潔な回答でも必要な内部工程を省略しない。
- snapshotは発走前の不変記録、receiptは読戻し・時刻適格性、recordは結果後の評価という境界を維持する。

### 3. 日別集計とサイクル集計を照合可能にする

- 各日別recordから対象race_id集合・KPI別の対象/適格/不適格/保留、投資・払戻、参照commitを集計する。同一日の再実行はrevisionを置換し、加算し直さない。
- 集計の検証を軽量なチェックで再現可能にする案を検討する。最低限、集合の重複・欠落、相互排他、snapshot/receipt参照、帳簿の混同、日別/サイクルの合計、別日PR統合時の上書きを検出する。実装形式は既存Markdownから無理なく検査できるかを先に小規模に試す。
- 自動化を導入しても外部レースデータ取得や予想判断は代行しない。検証不能な値を0や成功へ補完しない。

### 4. 第2サイクルを閉じて次回へ引き継ぐ

- 第2の集計は当時の契約と証跡をレースごとに監査して確定または保留とする。過去のsnapshot・買い目を結果から作り直さない。
- サイクル終了時は各仮説を昇格/継続検証/棄却/判断保留に分類し、適格件数、比較結果、欠測、非劣化、判断理由、参照commit、次回の取得条件を引継ぎ欄に残す。未実行を効果なしと判定しない。
- 正式ルール変更は審査後の別PRとし、現行サイクルが参照する文書や未終了データを一括削除しない。

## 受入条件

- 初回24Rから検証4R・購入3R（重複2R）を選ぶ例で、最終対象5R・回顧対象24Rを維持し、候補外19Rを最終欠測へ数えない。
- 同じレースを別チャット・翌日・別branchで再開しても元の基準予想と証跡を参照でき、未確認なら推測で再生成しない。
- 本体未保存、receipt未確認、発走時刻不明、結果未確定、Shadow未完了について、回答・KPI・回顧・一巡成功を独立判定できる。
- 日別のrace_id×KPI集合とサイクル合計が一致し、再実行・複数日PRの統合で重複加算・上書きがない。
- 第2の正式KPIと第3の実績を分け、保留・未測定・実測0を区別する。机上試験と実レースLIVEも混ぜない。
- 利用者向けの回答は予想・買い目・回顧・進捗の依頼に必要な内容に絞り、追跡用IDの説明を要求しない。
- 変更は作業ブランチから個別PRで行い、各PRで変更の本質をセルフレビューする。確認だけに作成した一時ファイルは含めない。

## 実施上の境界

本計画は設計・整理の提案であり、実レースの予想、過去成績の再確定、第2サイクル終了審査、現行ルールの昇格を実施した記録ではない。チャット環境がリポジトリを自動的に読む保証はないため、プロジェクト側には「`eda-hub/horse-man` の `main` の `docs/manual/README.md` と必要なOwnerを毎回参照する」という短い入口指示を残す。
