# 00_core — 共通実行契約

全モジュール共通の実行契約と境界を定義する。個別の能力評価・買い目・Shadow仮説・回顧ロジックは各Ownerモジュールへ委譲する。

# 競馬予想ルール原本

- **バージョン**: v1.6.1
- **最終更新日**: 2026-09-20
- **用途**: 中央競馬・海外競馬を含むレース予想の共通ルール原本

# まず読む用語

- **基本予想**：現在の正式ルールだけで作る予想。検証中の新しい仮説は混ぜない。
- **条件別補正**：重賞、若駒、当日馬場など、該当条件のときだけ追加する分析。
- **検証中ルール**：まだ正式採用していない新しい仮説。結果を比較して採用可否を判断する。
- **基準予想**：実際の正式な予想として保存する側。
- **比較予想**：検証中ルールを試した場合にどう変わるかを見る比較用の予想。
- **予想確信度**：オッズとは切り離した「予想そのものへの自信」。A / B / C / Dで表す。
- **購入確信度**：オッズ、買い目期待値、資金配分まで含めた「その馬券を買う自信」。A+〜C-で表す。
- **購入優先度**：開催全体の中で、どのレースを優先して最終検討するか。S〜Dで表す。
- **買い目期待値**：その買い目の的中確率とオッズを組み合わせた、価格面の期待度。
- **自然な組み合わせ監査**：印に入っている有力馬同士の自然な馬連・ワイド・三連系を、価格で削る前に一度すべて候補化する確認。
- **万能軸監査**：全買い目が1頭に依存しすぎていないかを確認する。
- **Production（正式系）**：正式な基準予想・基準確率・正式推奨買い目を作る系統。領域Aの正式ルールと領域Bの監査だけが決定権を持つ。
- **Shadow（比較系）**：検証中ルールを試す独立系統。基準予想をコピーして差分を作るが、Productionを上書きしない。
- **51A 重賞情報拡張**：重賞で馬自身の事実データを深く収集し、既存の正式ルールへ渡す情報収集プロトコル。独自の重賞傾向加点は行わない。
- **51B 重賞傾向Shadow**：過去傾向・年齢・ローテ集計・枠傾向・血統集計等の重賞固有モデルを比較用に適用するShadow分析。

# 0. ルール運用の全体構造

## 0.0 GitHubルールモジュール読込時の自動実行契約

`docs/manual/` 以下の本ルールシステムは、単なる参考資料ではなく、**競馬予想・回顧・検証を実行するための自己完結型の運用仕様**として扱う。

`README.md` と依頼に必要なモジュールをGitHubから読み込み、ユーザーが競馬予想・最終予想・WIN5・回顧・検証などを依頼した場合、ユーザーから詳細な手順指定がなくても、以下の規約を自動適用する。

### 0.0.0 HF1変更保護宣言 / Production-Shadow完全分離

本HF1は、**中身を変えるのではなく境界を直す緊急修正**である。

#### 保護対象

次の既存骨格は変更しない。

- 事実 → 解釈 → 予測の分離
- 基礎能力と今回発揮能力の分離
- 近走内容・相手レベル・成長・適性の評価
- レース質を先に作り、複数シナリオで考える構造
- 騎手・厩舎・血統を補助適性として扱う原則
- 最も勝つと思う馬 / 最も買いたい馬の分離
- ①期待値型 / ②少額高配当型 / ①＋② / 見送り
- 最終順位保全・確信度保全
- 万能軸監査（旧「自然な組み合わせ監査」はv1.6.0で券種選択後の自然な本線監査へ置換）
- 券種・組み合わせごとの買い目期待値独立評価
- モード7のユーザー指定条件内最適化

#### 決定権の原則

正式な基準予想・基準確率・正式推奨買い目へ直接影響できるのは、**領域Aの正式予想生成 / 正式条件別補正と、領域Bの監査による原因要素への差し戻し**だけとする。

領域C2の検証中ルール、51B、E-09、E-10、E-11、E-12等はShadow系であり、**基準順位・基準確率・正式推奨買い目を上書きしてはならない。**

ただしE-03 / E-08は価格観測・価格予測の共通入力としてProductionとShadowの双方で利用してよい。これらは能力順位・印・勝率を変更せず、価格判断・購入確信度・買い条件だけに作用する。

本文中の「成熟度：検証中」は、それだけでProduction使用禁止を意味しない。**参照権限は本0.0.0と0.0.6の論理領域を優先して決める。** 領域Aに明示的に残された既存ルールは第2サイクル中も保護し、今回のHF1を理由に無効化しない。

#### 逆流禁止

処理順序は、

**Production基準予想固定 → Shadow比較予想固定 → Production基準買い目固定 → Shadow比較買い目固定 → 発走 → 結果比較**

とする。

Shadowで良い案が見つかっても、同レースのProductionへ逆流させない。ユーザーが明示的にShadow案を選択した場合のみ実購入へ採用できるが、その場合も「正式推奨」と「ユーザー選択による実購入」を分離して保存する。

#### 同一レースの基準予想一意性

同一日・同一レースについて、同一バージョンで既に発走前の基準予想が固定されている場合、別チャット・別モードでもその基準予想を再利用する。

新しい非価格情報がないのに別チャットで基準予想をゼロから再生成しない。変更する場合は37.1 / 37.2に従い、変更前後・理由・証拠強度・情報時刻を保存する。

#### 基準予想ID / baseline_forecast_id

Production基準予想を固定した時点で、同一レースを識別できる `baseline_forecast_id` を付与する。形式は原則として、

`YYYYMMDD-競馬場-R-P連番`

とする。例：`20260912-HAN-11-P001`。

- 同じProduction基準予想を別チャットで参照するときは同じIDを使用する。
- 強い非価格情報によって正式更新した場合だけ新しい連番を発行し、旧IDとの変更理由を保存する。
- `30_betting.md`、`40_shadow.md`、`50_review.md` は必ず元の `baseline_forecast_id` を引き継ぐ。
- オッズ更新だけで新しいProduction基準予想IDを発行しない。

#### チャット予想のクリティカルパス最適化 — 優先度A / 2026-09-18

ChatGPT上の予想では、予想ロジックを変更せず、取得・再利用・記録の実行方法だけを最適化する。

##### 1. 分析途中と正式snapshot永続化を分離する

事前予想・最終予想・買い目を**考えている途中**では、記録目的のGitHub branch作成、commit、pull request、検証台帳更新を行わない。取得ログ、思考過程、未確定順位、未監査買い目は保存対象にしない。

一方、ProductionまたはProduction買い目を正式固定した時点では、後日の回顧で発走前記録を失わないため、**ユーザーへのチャット送信直前に最小の不変snapshotをGitへ永続化する。**

保存順序は原則として、

**分析・監査完了 → 正式内容FIXED → 発走前snapshot永続化 → 同内容をチャット送信**

とする。

保存先は `docs/validation/snapshots/YYYY-MM-DD.md` とし、同一日のsnapshotをappend-onlyで追記する。旧snapshotを上書き・削除して現在値だけにしない。正式更新が必要な場合は新しい `baseline_forecast_id` またはrevisionを持つ新snapshotを追記し、`previous_snapshot_ref` で直前snapshotを参照する。

最低限、snapshotは次を保持する。

- `snapshot_id`
- `snapshot_type`: WHOLE_DAY / INITIAL_PRODUCTION / FINAL_PRODUCTION / BETTING_FIXED / SHADOW
- race_id / 日付 / 競馬場 / R
- `baseline_forecast_id`
- `manual_release`
- `fixed_at_jst`
- `information_cutoff_jst`
- `previous_snapshot_ref`（更新時）
- Production順位・印・勝率 / 連対率 / 3着内率
- 予想確信度
- 選別区分・購入優先度（該当時）
- 当日馬体重取得状態
- `production_status`: NEW / REUSED / UPDATED
- 初期→最終変更がある場合の変更対象・非価格理由・証拠強度・情報時刻
- 市場を能力順位へ使用していないことの状態
- 買い目を固定した場合は、購入確信度、使用価格・取得時刻、固定買い目、最大馬依存率、購入前監査後判断
- 適用Shadowの完了 / 未完了状態

全体選別は対象全レースを1回のsnapshotへまとめてよく、個別最終では当該レースだけを追記してよい。これにより、予想速度への影響を最小化する。

snapshot永続化がGitHub障害・時間制約等で発走前に完了しない場合は、予想回答自体を発走に遅らせない。チャットへ同じ正式内容を送信し、`PRE_RACE_SNAPSHOT_PERSIST_FAILED` を明示する。そのsnapshotはGit永続化を結果後に後付けして「発走前永続化済み」と扱わず、KPI適格性は各Ownerの条件に従って判定する。

結果後の正式回顧・払戻・エラー分類・KPI集計は従来どおり `docs/validation/records/` へ保存する。発走前snapshotと回顧recordは役割を分離し、結果から発走前内容を作り直さない。

##### 2. race_evidence_bundleを一度作り、使い回す

同一レースで取得した事実データは、概念上の共通入力 `race_evidence_bundle` として扱う。

```text
race_evidence_bundle
├── static_evidence_snapshot
└── dynamic_evidence_snapshot
```

`static_evidence_snapshot` は、同一レースの予想期間中に通常は変化しない情報を持つ。

- 過去走・ラップ・相手レベル等の履歴
- 血統・牝系・クロス
- コース形態・距離の物理特性
- 過去の重賞傾向・長期集計
- 騎手・厩舎の過去実績など、取得時点以降に当該レースについて変化しない履歴情報
- ユーザーが事前に提示した蓄積heuristicの意味定義

`dynamic_evidence_snapshot` は時点依存情報を持つ。

- 出走取消・競走除外
- 騎手変更、装具等の直前変更
- 天候・馬場状態・当日バイアス
- 当日馬体重・増減
- 調教後に新たに判明した状態情報
- オッズ・人気・市場構造
- その他、取得時刻によって値が変わり得る情報

同じ情報をProduction用、51A用、51B用、E-09等Shadow用として別々に取り直さない。各ルールは同一bundleを異なる判断規則で参照する。

##### 3. 事前予想→最終予想は差分更新する

同じ `manual_release`、同じレース、同じ `baseline_forecast_id` の有効な事前予想がある場合、最終予想でゼロから分析をやり直さない。

1. 既存 `static_evidence_snapshot` を再利用する。
2. `dynamic_evidence_snapshot` だけを最新時点へ更新する。
3. 更新された事実が影響する能力要素・展開・状態・確信度・価格判断だけを差分再評価する。
4. 強い非価格情報で37.1 / 37.2の正式更新条件を満たす場合だけProductionを更新する。
5. 競走条件自体の変更、重大な事実誤認、データ破損等で静的snapshotが無効になった場合のみ必要範囲を再構築する。

##### 4. ProductionとShadowで取得を重複させない

Production基準予想固定後、Shadowは原則として同じ `race_evidence_bundle` を入力にして差分評価だけを行う。Shadow固有仮説の評価に必要な事実がbundleに存在しない場合のみ追加取得できるが、取得済みの同一事実を別ソース探索のためだけに再取得しない。

ProductionとShadowの**判断順序**は従来どおり直列とし、ShadowをProductionへ逆流させない。一方、Production固定前に必要と分かっている独立した事実取得は並列化してよい。

##### 5. 独立した取得は並列化する

実行環境が対応する場合、相互依存しない取得は可能な限り同時に開始する。

- 依頼に必要と判明した複数manualモジュールの読込
- レース固有Git記録とルール文書の読込
- 公式出馬情報と、別系統の過去走・血統等の取得
- 複数馬について相互依存しない履歴情報の取得
- Production / Shadow双方が後で使う共通事実の収集

ただし、先行処理の結果で対象が決まる処理、同一ファイルへの書込、Production固定後でなければ意味が決まらないShadow差分評価は直列のままとする。

##### 6. 再利用可否を明示する

再利用した情報には、可能な範囲で取得元・取得時刻・対象範囲を保持する。時点依存情報を古い値のまま最新情報として扱わない。「再取得しない」と「鮮度確認をしない」は同義ではない。

### 0.0.1 短い依頼を完全な実行指示へ展開する

ユーザーの指示が短くても、本ルールシステムに定義された必須工程を省略してよいとは解釈しない。

例：

- 「札幌11R」
- 「中京7Rお願いします」
- 「最終予想」
- 「今日の全レース」
- 「WIN5」
- 「このレースを回顧」

のような短い依頼でも、対象が特定できる場合は、`README.md` の読込規約に従って必要モジュールを取得し、該当モード・標準フロー・必須出力を自動的に展開して実行する。

ユーザーが明示的に「簡潔に」「買い目だけ」「確率だけ」など出力範囲を限定した場合のみ、表示量を縮小してよい。ただし内部の基準予想生成・必要条件別補正・監査まで省略したものとして扱わない。

### 0.0.2 実行モードを自動判定する

依頼内容から次のモードを自動判定する。

#### モード1：単一レース・基準予想

以下のように特定の1レースが指定された場合に使用する。

- 日付＋競馬場＋R
- 競馬場＋R
- レース名
- 会話文脈から対象が一意に確定する「このレース」「最終予想」等

実行順序は原則、

**情報取得 → 領域A 基準予想 → 必要な正式条件別補正 → 領域B 監査 → （検証サイクルではモード5比較用予想固定） → 市場比較 → 買い目 → （比較用買い目固定） → 検証記録用サマリー**

とする。

**領域Cの比較用予想を基準予想へ混入させない。** ただし正式検証サイクル中は、0.0.2のモード5自動実行条件に従い、ユーザーの明示がなくても基準予想固定後に比較予想を別系統で自動作成し、発走前チャットsnapshotへ固定する。

#### モード2：開催全体の選別

以下の依頼で使用する。

- 「今日の全レース」
- 「本日の中央競馬」
- 「買いレース候補」
- 「開催全体を見て」

開催全体を全体選別し、既存ルールに従って、

- ①期待値型
- ②少額高配当型
- ①＋②
- 見送り

へ分類し、買い候補を**購入優先度（S / A / B / C / D）**付きで提示する。

午前中は当日情報を無理に補完せず午前モード、十分な実測サンプルが蓄積した場合のみ午後当日実測補正モードを使用する。

#### モード3：WIN5

「WIN5」の予想・買い目・検証を依頼された場合に使用する。

通常の各対象レース予想を先に作り、その後にWIN5補正を適用する。通常馬券の妙味順位をそのままWIN5候補へ流用しない。

WIN5補正は使用範囲としては正式条件別補正だが成熟度は検証中ルールであるため、結果は継続検証対象として記録する。

#### モード4：回顧・検証

結果確定後に、

- 「回顧」
- 「振り返り」
- 「検証」
- 「反省と改善」

等を依頼された場合に使用する。

発走前に保存された予想を基準とし、結果を知った後の情報を事前判断へ逆輸入しない。

基本予想 / 条件別補正 / 検証中ルール / 価格判断 / 買い目構造 / 資金配分を分離して採点する。

新しい改善案は原則として領域Cへ検証候補として記録し、基準予想を直接変更しない。

#### モード5：基準予想と比較予想の比較

基準予想を基準に検証中ルールの差分価値を検証するモード。

通常時は、ユーザーが、

- 「検証中ルールも試して」
- 「比較予想と比較して」
- 「E-03を適用して比較」

等と明示した場合に使用する。

ただし、**正式な検証サイクルではユーザーの明示依頼を待たず自動実行する。**

第2検証サイクル（2026-09-12・13・19・20・21・22）では、次をモード5自動実行対象とする。2026-09-22は、台風25号の影響で2026-09-21の中山競馬が延期されたことによる代替開催日として追加する。

- モード1で最終予想を作成する全レース
- モード2で購入候補へ昇格したレース（① / ② / ①＋②）
- 全重賞（重賞詳細分析対象）
- ユーザーが個別に最終予想・買い目を求めたレース

開催全体の選別で「見送り」としたレースは、詳細な比較予想計算を必須としない。ただし、**結果確認前に「見送り／比較予想の詳細比較省略」または該当検証中ルールの有無を記録**し、結果後に都合よく比較予想を再構成しない。

自動モード5では必ず、

1. **先に基準予想・確率・印・予想確信度を完成して保存・固定する**
2. 重賞では51B、その他はE-09 / E-10 / E-04 / E-07等、そのレースに該当するShadow比較予想を適用する
3. 比較予想側では順位・確率を実際に動かしてよいが、基準予想は変更しない
4. 基準予想→比較予想で「何が、なぜ、どの程度動いたか」を結果確認前に保存する
5. Production基準買い目を先に固定した後、E-11 / E-12等のShadow比較買い目を別途生成し、基準買い目と**同一オッズ時点**で評価して各購入確信度を並行保存する。比較結果で正式推奨を差し替えない
6. **基準予想と比較予想の双方を発走前に固定する**
7. 結果後に改善・中立・悪化、確率校正、買い目・回収率を比較する

の順を守る。

**比較予想によって基準予想を上書きしない。** モード5の目的は、その場で正式予想を変更することではなく、次回サイクル終了審査に使える前向き比較データを自動的に蓄積することである。

ユーザーが「今回は比較予想との比較不要」と明示した場合のみ、そのレースの自動モード5を省略してよい。

#### モード6：サイクル終了審査

2週間・最大約144Rの検証サイクル終了時に使用する。

予想精度、確率確率精度の検証、①②別成績、午前午後差、当日実測補正、価格判断、馬券構造、検証中ルール成績を集計し、

- 据え置き
- 継続検証
- 統合
- 昇格候補
- 降格・棄却

を審査する。

サイクル終了を理由に基準予想を必ず改訂しない。


#### モード7：ユーザー選択後の購入最適化

事前予想または最終予想を提示した後、ユーザーが、

- 買いたい馬
- 使用したい券種
- 予算

の全部または一部を指定した場合に使用する。

例：

> ①④⑤を使って、馬連・ワイド・三連複を3,000円買いたい

この場合、最初の予想を作り直すのではなく、**保存済みの基準最終予想・確率・市場評価を固定したまま、ユーザーが指定した購入条件の範囲内で最終買い目を最適化する。**

原則として、

1. 保存済みの最終印・勝率・連対率・3着内率を固定する
2. ユーザーが選んだ馬を「購入対象馬」として抽出する
3. ユーザーが指定した券種だけを「許可券種」とする
4. 最新の取得可能オッズを確認する
5. 購入対象馬 × 許可券種から成立する買い目候補を列挙する
6. 各候補を、予想確率・同時好走確率・価格・相関・本線シナリオとの整合性から比較する
7. 低い期待値・重複性の高い買い目は、ユーザーが指定した券種であっても機械的には採用しない
8. 採用買い目へ予算を100円単位を基本として配分する
9. 最終買い目、金額、役割、本線／押さえ／高配当の区分を提示する

とする。

ユーザーが選択していない馬や券種を、正式な最終買い目へ勝手に追加しない。追加すると明確に改善余地がある場合は、**指定条件内の最適案とは分離して「参考代替案」**として提示する。

「予算3,000円」のような表現は原則として上限予算として扱う。ただし「3,000円分買う」「3,000円使い切る」等、総額使用の意思が明確な場合は指定総額へ合わせる。

ユーザーが選んだ馬の中に基準予想上位馬が含まれていなくても、価格だけを理由に基準予想を変更したり、選択外の上位馬を強制的に買い目へ戻したりしない。予想と購入意思決定を分離する。

### 0.0.2.1 重賞の自動判定と重賞詳細分析起動

対象レースがJRAのGⅠ・GⅡ・GⅢ、または海外のグループ／グレード競走等の**重賞**であると判定できる場合、ユーザーから追加指示がなくても51を自動起動する。

HF1以降、51は次の2系統へ分離する。

- **51A 重賞情報拡張（Production側）**：馬自身の前走内容、同条件実走、5代血統、枠×脚質、騎手、厩舎、当日一次情報等を深く収集する。得た事実は既存の正式ルール1〜37等へ渡して評価する。51A自身は独立した加点表・順位補正を持たない。
- **51B 重賞傾向Shadow（Shadow側）**：過去レース集計、年齢・性別傾向、前走ローテ集計、枠順集計、血統集計、人気構造等の重賞固有傾向を比較用に適用する。51Bは基準順位・基準確率・正式推奨買い目を変更しない。

重賞では必ず、

**基本予想 → 51Aで事実拡張 → 正式条件別補正 → 基準予想固定 → 51B Shadow比較**

の順を守る。

「前走同コース勝ち」のような**当該馬自身の直接証拠**は51Aから既存正式ルールへ渡してProductionで評価できる。一方、「過去10年で3歳馬が強い」のような**集団傾向**は51BとしてShadowだけで評価する。

ユーザーが「通常予想だけ」「重賞詳細分析不要」等と明示した場合は51A / 51Bとも省略できる。

### 0.0.3 対象レースの自動解決

ユーザーが対象を完全には書いていなくても、現在の会話・日付・直前の発言から対象レースを一意に解決できる場合は、再質問せずその対象で実行する。

また、以下のように外部から確認できる情報は、原則としてユーザーへ入力を求めず取得を試みる。

- 発走時刻
- 出馬表・馬柱
- 枠順
- 騎手
- 斤量
- 取消・除外・騎手変更
- 馬体重
- 天候・馬場状態
- オッズ
- 同日同競馬場の既終了レース
- 確定結果・払戻

情報源は可能な限りJRA等の主催者公式・一次情報を優先する。

ただし、ユーザーの予算、購入済み馬券、独自の資金上限など、外部取得できない意思決定情報は推測しない。

予算指定がない場合は、具体的な総額を勝手に仮定せず、原則として**買い目の優先順位または資金配分比率**で提示する。

### 0.0.4 ルールだけが読み込まれ、対象依頼がない場合

ルールシステムだけが読み込まれ、予想対象・回顧対象・作業目的を会話から一意に特定できない場合は、勝手に当日の全レース予想を開始しない。

この場合のみ、必要最小限として**対象レースまたは作業目的**を確認する。

ただし、同一メッセージまたは直前文脈から対象が明確なら確認を挟まず実行する。

### 0.0.5 情報時点を自動判定する

現在時刻と発走時刻から、原則として次を自動判断する。

- 発走前・当日サンプル不足 → 午前／事前モード
- 発走前・関連レースの実測情報が十分 → 午後当日実測補正候補
- 発走直前 → 最終予想として最新の取得可能情報を確認
- 発走後・結果未確定 → 確定前情報と推測を区別
- 結果確定後 → 回顧モード

結果確定後に事前予想を依頼された場合は、結果を混ぜた疑似的な事前予想を正式な前向き検証データとして扱わない。

### 0.0.6 モジュール構成と論理領域・参照権限

本ルールシステムは `docs/manual/` 配下の複数モジュールで運用し、`README.md` を唯一の入口とする。論理上は以下の4領域を維持し、物理モジュールと論理領域の双方でProduction / Shadowの境界を固定する。

#### 領域A：基準予想

正式な予想生成に使用する基準領域。

対象：

- 本文の基本予想生成ルール
- 0.13で基本予想と定義された項目
- 0.13で条件別補正と定義された既存条件別補正
- 標準予想フロー
- 単一レースモード
- 開催全体の選別
- WIN5依頼時の既存WIN5補正
- 重賞指定時に自動起動する**51A 重賞情報拡張**。51Aで得た馬自身の事実は既存正式ルールへ渡すが、重賞固有の集団傾向は51Bへ分離する

通常の正式予想では必ず領域Aを基準とする。

#### 領域B：監査

基準予想の矛盾・暴走・二重計上・過度な資金集中を検出する監査領域。

対象：

- 0.2「予想生成と監査の分離」
- 0.13の基本監査
- 二重計上
- 印と確率順位の整合性
- 不確実性レンジ
- 情報時刻整合
- 馬依存率・シナリオ依存率
- 反実仮想
- 非劣化確認に関する運用規約

領域Bは通常予想でも使用するが、**独立した加点・減点材料として能力順位を動かさない。**

問題を検出した場合のみ、原因となる領域Aの評価要素へ戻って修正する。

#### 領域C：比較予想・検証中ルール

新しい仮説・馬券構築方法・価格再走査などの検証領域。

対象：

- 「検証中ルール追加記録」のうち未昇格項目
- **51B / E-04 / E-07 / E-09 / E-10 / E-11 / E-12**および次サイクルの比較予想候補。E-03 / E-08は0.0.0の共通価格入力特例に従う
- 検証課題一覧のうち新しい予想・馬券仮説

E-01・E-02・E-05はv1.5.0で正式ルールへ昇格し、E-06は基本運用規約として確立したため、通常の領域C 比較予想としては扱わない。旧節は検証履歴として残す。

通常のモード1・モード2の正式予想では、**領域Cを基準予想生成・基準確率・基準印へ直接反映しない。**

モード5では、基準予想固定後に指定または検証計画で自動指定された検証中ルールだけを比較予想へ差分適用する。第2検証サイクルでは0.0.2のモード5自動実行条件を満たすレースについて、ユーザーの明示依頼なしでE-09 / E-10等の該当比較予想を発走前に保存する。

#### 領域D：検証記録

過去の個別レース結果、ケーススタディ、検証サマリー、検証中ルールの実績を保存する記録領域。

対象：

- 2026-08-29等の具体的な検証記録
- レース固有の成功・失敗例
- 検証中ルール適用結果
- サイクル集計
- 更新履歴

領域Dは、モード4・モード5の結果比較・モード6の集計では参照してよい。

一方、通常の事前予想では、**過去ケースの結果をそのまま新レースの能力評価・印・確率形成の根拠として使用しない。**

必要な一般化がある場合は、領域Cの仮説として明示的に検証する。

### 0.0.7 検証中ルール内の役割分離

領域C内でも、次の2種類を区別する。

#### C1：検証プロトコル

予想内容そのものを変更せず、検証の質を高める仕組み。

v1.5.0では良好部分保全 / 非劣化ガードと基準予想 / 比較予想方式は正式運用規約へ昇格した。

今後C1には、予想内容そのものを変更せず検証品質だけを改善する新しいプロトコル候補を置く。正式運用規約は領域Bおよび0.16.1等に従って常時使用する。

#### C2：予想・馬券比較予想

基準予想とは異なる判断・買い方を試す新仮説。

代表例：

- 最終価格再確認
- 位置取り主導権補助評価
- 高確信度活用
- 最終オッズ予測（実戦検証中ルールとして別途自動適用特例あり）
- その他の条件付き着順・買い目構造の新仮説

C2はモード5または検証計画で指定された場合のみ適用する。

### 0.0.8 通常予想での検証中ルール遮断

通常の正式予想を依頼された場合、以下をデフォルトとする。

> **Productionは領域Aで基準予想を作成し、領域Bで監査する。Shadow系の領域C2は基準順位・基準確率・正式推奨買い目へ逆流させない。領域Dの過去結果は予想生成へ使用しない。**

第2サイクルの扱いは次のとおり。

- **E-03 / E-08**：価格観測・価格予測の共通入力。能力順位・印・勝率へ逆流させず、Productionの価格判断・購入確信度・買い条件に利用できる。
- **51B / E-09 / E-10 / E-04 / E-07**：Shadow比較予想だけを作成する。基準予想を変更しない。
- **E-11 / E-12**：Production基準買い目固定後にShadow比較買い目だけを生成する。比較結果を見て正式推奨を差し替えない。

ユーザーがShadow案を明示的に選択した場合は実購入へ採用できる。その場合も、

- Production正式推奨
- Shadow比較案
- ユーザー選択による実購入

を別々に保存する。

この原則は、本文下位節に「比較して最終決定」「検証中ルール補正」等の旧表現が残る場合より優先する。HF1では該当主要箇所を同時に正規化する。

### 0.0.9 回顧時の参照範囲

回顧・検証時は領域A〜Dを参照してよい。

ただし、

- 基準予想が当時どう判断していたか
- 比較予想なら何が変わったか
- 結果を知った後だけ成立する説明ではないか

を明確に分ける。

回顧結果から領域Aを直接書き換えず、サイクル中は領域Cまたは領域Dへ保存する。

### 0.0.10 自動実行時の最低出力保証

ユーザーから特別な省略指定がない場合、単一レースの正式予想は原則として0.18の標準出力を自動実行する。

開催全体では49-9、WIN5では50およびWIN5標準フロー、回顧では40〜43と標準予想フローEを基準にする。

「最終予想お願いします」など短い依頼であっても、短い依頼であることだけを理由に、

- 基本予想順位
- 3大要因
- 必要条件別補正
- 確率
- 予想確信度
- 購入確信度（市場未取得時は未判定）
- 購入優先度（開催全体モード時）
- 市場比較
- 最も勝つ馬 / 最も買いたい馬
- 買い条件
- 買い目
- 依存率監査
- 情報基準時刻

を無断で省略しない。

### 0.0.11 本自動実行契約の優先順位

実行時の優先順位は、原則として次のとおりとする。

1. ユーザーがその依頼で明示した指示
2. 本0.0「自動実行契約」
3. 領域A 基準予想 / 正式条件別補正
4. 領域B 監査
5. 領域C 検証中ルール
6. 領域D 検証記録

ただし、ユーザーが単に短く依頼したことは「本ルールシステムの必須工程を省略せよ」という明示指示とは扱わない。

本0.0は**予想ロジックを変更するルールではなく、複数モジュールを一貫して実行するための運用契約**である。

本原本は、予想精度を高めるためにルールを無制限に増やすのではなく、**重要な判断を鋭く保ちながら、必要な場面だけ追加情報を使う**ことを目的として、以下の3層で運用する。

## 0.1 基本予想 / 条件別補正 / 検証中ルール の3層構造

### 基本予想 — 全レースで使う固定基盤

基本予想は、原則として全レースで必ず使う予想の骨格である。

主な内容は、

- 事実 → 解釈 → 予測の分離
- 基礎能力と今回発揮能力の分離
- 近走内容・相手レベル・現在地
- 今回要求される能力
- レース質・ペース・位置取り
- 複数シナリオ
- 勝率・連対率・3着内率
- 市場オッズとの比較
- レース予想と馬券戦略の分離
- 回顧時の予想・価格判断・馬券結果の分離

とする。

基本予想の役割は**予想を作ること**であり、毎回の失敗をすべて防ぐことではない。

### 条件別補正 — 条件に該当するときだけ使う補助層

条件別補正は全レースで機械的に適用しない。

代表例：

- **若駒・操縦性条件別補正**：2歳馬、キャリア浅い馬、初回り・初コースなど
- **昇級・未知条件別補正**：クラスアップ、初距離、初条件など
- **当日馬場補正**：当日の複数レースから有効な馬場・位置取り情報が得られた場合
- **情報品質条件別補正**：情報の鮮度・信頼度・時刻整合性に問題がある場合
- **高配当条件別補正**：②少額高配当型、穴軸・妙味軸を検討する場合
- **WIN5補正**：WIN5を購入・検討する場合
- **51A 重賞情報拡張**：GⅠ・GⅡ・GⅢ等の重賞で、当該馬の5代血統・前走・同条件実走・枠×脚質・騎手・厩舎・当日データを深掘りし、既存正式ルールへ事実を供給する。重賞固有の集団傾向は51B Shadowへ分離する

該当しない条件別補正は読み飛ばしてよい。

### 検証中ルール — 新しい仮説の検証層

個別レースの回顧から得た新しい改善は、原則として直ちに基本予想へ追加しない。

まず検証中ルールとして、

- 仮説
- 適用条件
- 期待する改善
- 予想をどう変更したか
- 実戦結果
- 反証例

を記録する。

検証中ルールは**予想を作る中心材料ではなく、基本予想に対する限定的な補正候補**として扱う。

## 0.2 「予想生成」と「監査」を分離する

ルール肥大化による予想のフラット化を防ぐため、ルールを次の2種類に分ける。

### 予想生成ルール

馬の能力順位・確率を実際に作る材料。

例：

- 近走内容
- 相手レベル
- 今回要求能力
- 距離・コース適性
- 展開適合
- 成長・状態
- 騎手・厩舎・血統による今回条件への適合補正（単純なブランド加点は禁止）

### 監査ルール

予想が暴走・矛盾していないか確認する材料。

例：

- 二重計上チェック
- 情報の証拠強度
- 不確実性レンジ
- 印と確率順位の整合性
- 馬依存率・シナリオ依存率
- 反実仮想チェック

**監査ルールを独立した加点・減点項目として扱わない。**

監査で問題が発見された場合のみ、原因となる予想生成要素へ戻って修正する。

これにより、確認項目が増えるほど全馬の確率が中央へ寄ることを防ぐ。

## 0.3 各レースで「予想を決めた3大要因」を先に固定する

最終評価前に、そのレースの予想を最も左右する要因を**原則3つまで**明示する。

例：

1. 現級での基礎能力
2. 今回の高速巡航適性
3. 好位を取れる確率

3大要因は単なる要約ではなく、**上位馬と中位馬を分ける主要因**とする。

その他の材料は、原則としてこの3大要因を補強・反証するために利用する。

重要度の低い多数の材料を均等に加点し、評価差が消えることを避ける。

ただし、重大な状態情報・取消・馬場急変などがあれば3大要因を更新してよい。その場合は変更理由を記録する。

## 0.4 基本予想を先に保存し、ProductionとShadowを分岐する

各レースでは、次の6段階を分けて記録する。

### A. 基本予想

当日バイアス・Shadow仮説を入れる前の基礎予想。

記録するもの：

- 上位評価
- 勝率・連対率・3着内率
- 予想確信度
- 予想を決めた3大要因

### B. 正式条件別補正

領域Aに属する正式条件別補正だけを適用し、基本予想から何を変更したか記録する。

例：

> 基本予想勝率24% → 公式当日馬場の強い補正 +2pt → Production基準26%

51Aは情報収集を深くする工程であり、51Aという名前だけで独立加点しない。

### C. Production基準最終予想固定

Bまでの印・確率・予想確信度を正式な基準予想として保存・固定する。

**ここから先のShadow分析はCを上書きしない。**

### D. Shadow比較予想

51B / E-09 / E-10 / E-04 / E-07等、該当する検証中ルールをCのコピーへ差分適用する。

例：

> Production勝率26% → 51B Shadow +1pt → Shadow勝率27%

この27%をProductionの26%へ戻してはならない。

### E. Production基準買い目固定

市場価格と比較し、35.1・45・48・49等の正式購入ルールでProductionの正式推奨買い目を作成・固定する。E-03 / E-08は価格共通入力として使用できる。

### F. Shadow比較買い目

E-11 / E-12等を使って比較買い目を別途生成し、Eと同一オッズ時点で保存する。Shadow案の方が良く見えても、Production正式推奨へ差し替えない。

結果後にA〜Fを分離して比較することで、

- 基本予想だけの方が良かったか
- 正式条件別補正が精度を上げたか
- Shadow予想が改善 / 中立 / 悪化だったか
- Production買い目とShadow買い目のどちらが優れていたか

を前向きに検証する。

## 0.17 単一レースモード — 別チャットで1レースだけ予想する場合

本ルールシステムは開催全体の全体選別だけでなく、**別チャットで指定された1レースだけを独立して予想する用途**にも使用できる。

ユーザーが競馬場・日付・Rまたはレース名を指定して1レースの予想を依頼した場合は、**単一レースモード**を使用する。

単一レースモードでも、

- 事実・解釈・予測の分離
- 予想を決めた3大要因
- 基本予想
- 該当条件別補正による差分
- レース質・複数シナリオ
- 勝率・連対率・3着内率
- 不確実性レンジ・予想確信度
- 購入確信度（市場取得前は未判定）
- 印と確率順位の整合性
- 市場オッズとの比較
- 最も勝つと思う馬 / 最も買いたい馬
- ① / ② / ①＋② / 見送り
- 馬券構造・依存率監査

は省略しない。

他チャットの過去会話や記憶がなくても、**このファイルとそのレースの事前情報だけで予想を完結できる**ことを原則とする。過去チャット固有の評価を暗黙に持ち込まない。

予算が指定されている場合は具体的な金額で買い目を提示する。予算が指定されていない場合は、無理に金額を仮定せず**資金配分比率**または買い目の優先順位を示す。

# 1. 大原則

予想の目的は、まず**レースそのものを正しく予測すること**とする。

単勝・複勝・ワイド・三連系などの馬券種から逆算して各馬の評価を変えない。

基本順序は以下。

**レース分析 → 各馬評価 → 着順・好走確率推定 → 市場評価との比較 → 馬券戦略**

したがって、

- ◎＝必ず単勝を買う馬ではない
- 複勝向きだから◎にはしない
- 穴だから評価を上げない
- 人気だから評価を下げない
- レース予想と馬券戦略は明確に分離する

---

# 2. 事実・解釈・予測を分離する

各材料を必ず、

**事実 → 解釈 → 今回への予測**

の順で扱う。

例：

- 事実：前走上がり最速
- 解釈：終盤性能は高かった
- 予測：今回も同じ脚を使えるかは、位置取り・ペース・馬場を別途検討

「上がり最速だから今回も差せる」のように、途中の論理を飛ばさない。

レース後も、

- データ認識が間違っていたのか
- データの解釈を間違えたのか
- 今回への適用を間違えたのか

を区別する。

# 別チャットでの利用方法

本ルールシステムは、**新しいチャットでもGitHubの `docs/manual/README.md` から必要モジュールを読み込み、1レースだけを独立して予想する用途**を正式な使用方法とする。過去チャットの文脈がなくても、GitHub上の現行ルールだけで予想を完結させる。

## 1レースだけ事前予想する場合

例えば次のように指示する。

> GitHubの `docs/manual/` にある現行ルールを読み込み、2026年○月○日○○競馬場○Rを単一レースモードで予想してください。現時点で取得できる事前情報だけを使用し、基本予想→Production正式条件別補正→Production基準予想固定→Shadow比較→Production基準買い目固定→Shadow比較買い目の順で、確率・印・買い条件・買い目まで提示してください。

この依頼では指定レースだけを深く分析し、開催全体の購入候補選定は行わない。

## 発走直前に最終予想する場合

> GitHubの `docs/manual/` にある現行ルールを読み込み、○○競馬場○Rの最終予想をしてください。直前オッズ・馬体重・取消変更・確認できる当日傾向を反映し、最初の基本予想から何を変更したかも明示してください。

同じチャットに事前予想がある場合はそれをProduction基準として使用する。別チャットの場合も、同一日・同一レース・同一バージョンの発走前Production基準予想がプロジェクト内記録等から参照可能なら、**新規再計算せず必ず再利用する。** 参照可能な保存済み基準予想がない場合だけ、その時点で取得可能な事前情報から基準予想を再構成し、「保存済みProduction基準なしの再構成」であることを明示する。

## レース後に回顧する場合

> 発走前に保存した予想と確定結果を比較し、基本予想 / 条件別補正 / 検証中ルール / 価格判断 / 馬券構造を分離して回顧してください。改善案は原本へ即反映せず、検証候補として記録してください。

回顧では結果を知った後に新しい事前根拠を作らず、発走前に利用可能だった情報と保存済み予想を基準にする。

## 開催全体から①②を選出する場合

従来どおり、

> GitHubの `docs/manual/` にある現行ルールを読み込み、本日の中央競馬全レースを全体選別して①期待値型、②少額高配当型、①＋②、見送りに分類してください。

と指示できる。

つまり本ルールシステムは、

- **単一レースを深掘りする用途**
- **開催全体から購入候補を選出する用途**
- **WIN5を検討する用途**
- **レース後に検証ログを作る用途**

のすべてで同一の基本予想を共有する。

個別レースのチャットでは、

- 馬柱
- オッズ
- 当日馬場
- 馬体重・取消変更
- レース結果
- 個別回顧

を扱う。

本原本には個別レース固有の結論を直接蓄積せず、回顧で得た内容はまず検証候補として保存する。**2週間の検証サイクル中は、個別レースの結果だけを理由に基本予想を書き換えない。**
